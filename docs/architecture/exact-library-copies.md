# Точные копии локальных файлов

Пакет 9 скрывает точные копии в «Моей музыке» и среди кандидатов «Волны». Это представление существующих записей, без удаления или объединения ID. Схема SQLite остаётся 9: используется прежняя nullable-колонка `tracks.content_hash`.

## Основание для совпадения

`Sha256FileContentHasher` читает весь файл потоком в отдельном isolate. Сохраняется ключ `file-sha256-v1:<число байтов>:<SHA-256>`. Имя, путь, теги, продолжительность и `stableId` не являются доказательством идентичности. Старые/неизвестные значения `contentHash` не участвуют в скрытии.

Явное сканирование повторно читает байты, включая неизменившиеся размер и mtime. Это обнаруживает подмену содержимого с сохранёнными атрибутами; цена — дополнительное чтение диска при пересканировании. Файл целиком не загружается в память, хэшируется один файл за раз. Долгое сканирование/отмена и более избирательное чтение остаются задачами этапа 3.

Размер, mtime и change time проверяются до/после чтения, число прочитанных байтов сверяется с размером. После чтения тегов/сохранения обложки атрибуты проверяются снова. Замеченное изменение или ошибка чтения запрещает публикацию старого хэша. Ошибка хэширования сама по себе не мешает импорту читаемых тегов; известная запись сохраняется с `contentHash = null`. Это не блокировка внешнего редактора: данные описывают последний успешный обход, постоянного наблюдения за файловой системой пока нет. После внешних изменений требуется пересканирование. Разные теги/встроенные обложки/кодировки меняют байты, такие файлы остаются отдельными.

## Запись результатов

Новый/изменившийся трек получает проверенный ключ при обычном upsert по ID/пути. Старые записи получают ключи также при пропуске неизменившихся тегов. Если прежний проверенный ключ изменился при тех же размере/mtime, теги читаются заново. `TrackContentHashRepository` пишет пакетно только колонку хэша, не перезаписывая параллельную ручную правку тегов. При ошибке проверки/метаданных прежний хэш обнуляется. `Track.copyWith(contentHash: null)` явно очищает значение; отсутствие аргумента сохраняет его.

## Представление и доступность

Репозитории по-прежнему возвращают все файловые записи; они нужны для привязки источников, управления библиотекой и сохранения пользовательских данных. Сначала исключаются отключённые источники, затем применяется поиск/фильтр отсутствующих, затем `withoutExactTrackCopies`. Среди совпадений выбирается доступная по результату сканирования запись, затем наименьший сохранённый ID, затем путь. Выбор не зависит от сортировки или порядка выдачи БД. Поиск по пути второй копии может показать именно её. Если одна копия отмечена отсутствующей или её источник отключён, видна оставшаяся активная. Пропадание файла после сканирования обрабатывается прежним аудиосервисом; живого переключения на альтернативный путь в этом пакете нет.

«Показывать точные копии» раскрывает все записи и участвует в ключе кэша видимого списка. Выбор трека передаёт в очередь именно видимый порядок, поэтому по умолчанию в контекст библиотеки попадает одна копия. Переключатель сбрасывается при новом запуске приложения. «Проиндексировано» по-прежнему считает файловые записи; «Видимых» — строки после фильтров.

Оценки, история и ручные правки остаются у исходных ID и автоматически между ними не переносятся. У другой выбранной копии могут быть другие ранее сохранённые оценки. Плейлисты, их порядок и явно составленная очередь не переписываются. Рекомендации применяют тот же выбор одной копии к активным кандидатам перед прежним расчётом баллов; переработки алгоритма/объединения предпочтений нет. Общая логическая запись с несколькими файловыми источниками остаётся отдельной задачей этапа 3.

Дополнение пакета 10: прогресс и остановка обхода реализованы; подробности в [заметке о сканировании](cancellable-library-scanning.md). Хэш читается блоками 64 KiB с обязательным закрытием файла до возврата отмены. Остановка сохраняет прежний хэш прерванного файла, не подменяя её ошибкой чтения. Требование явного пересканирования после внешних изменений остаётся прежним.

Дополнение пакета 13: штатный обход переиспользует один lazy hash-worker на папку, ReadInto читает блоками до 256 КиБ (малые файлы — меньше). Каждый запрос закрывает свой файл и канал отмены до ответа; worker завершается при close сессии до результата/диагностики сканирования. Старый одиночный путь сохраняет 64 КиБ. Правила отмены/побайтового совпадения остаются прежними. Подробный профиль и границы: [оптимизация импорта](import-performance.md).
