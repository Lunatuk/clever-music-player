# Короткая история «Волны» — пакет 18

Гипотеза пользователя подтверждена в общей очереди: `_finishTrackListContext`
после конца списка вызывает `_chooseAndPlaySmartNext(enableWave: true)`;
подготовленный `_buildNextPlan` также имеет fallback в Wave. `_playWaveSelection`
обнуляет контекст списка, поэтому прежний `previous()` до порога пяти секунд
ничего не делал вне списка/плейлиста. Выбор «Волны» использует прежний взвешенный
подбор и защиту от повторов; на четырёх файлах возможны частые повторные визиты.
Проблем со звуком пользователь не наблюдает. Это не дефект порядка самого списка.

## Контракт

- После конца библиотеки/плейлиста сохраняется прежний переход в «Волну».
- `_WaveHistory` уровня `PlaybackQueueService` держит максимум **шесть Track**:
  пять предыдущих визитов плюс текущий. После Back будущие визиты занимают те же
  слоты; новые массивы полной медиатеки, контексты плейлистов, кандидаты с баллами,
  байты аудио/картинок не сохраняются. Это история визитов, одинаковые ID допустимы.
- При первом входе в «Волну» предыдущий загруженный трек становится началом
  цепочки: можно вернуться с первой рекомендации на последний трек списка.
  Весь старый список не удерживается и его контекст при возврате не восстанавливается.
- Новая рекомендация добавляется после завершения команды проигрывателя,
  если источник не завершился playback error. Ошибка записи статистики при
  продолжающемся звуке сама по себе не отменяет визит. Предзагрузка не добавляет
  историю. Неудавшаяся новая загрузка оставляет прошлый сохранённый визит.
- Previous до/на пяти секундах идёт назад по истории. После пяти секунд первое
  нажатие перематывает к началу, второе идёт назад — как в прежних списках.
  На старой границе история не зацикливается: остаётся начало текущего трека.
- Next после Back сначала идёт вперёд по сохранённым визитам. После последнего
  вновь используется прежний выбор Wave. Естественное завершение/crossfade
  следуют тому же плану. Явный запуск новой рекомендации через `playSmartNext`
  может создать новую ветку, удалив прежние будущие визиты.
- Ручная очередь имеет прежний приоритет над историческим Next. Её запуск,
  явный выбор одиночного трека и переход на список начинают новую цепочку.
  Repeat/shuffle и навигация внутри списка остаются на прежних ветках кода.
- History replay читает актуальную запись через прежний `_resolvePlayableTrack`:
  удалённые и `isMissing` пропускаются, обновлённые теги/источник/ID используются.
  Физическая недоступность проверяется самим плеером; ручная ошибка не запускает
  автоматический поиск другого трека. Правила disabled folders остаются теми же,
  что у прежнего resolver списка; нового глобального фильтра здесь нет.
- При replay не сохраняются старые баллы/объяснения рекомендации: они очищаются.
  Текущий лайк перечитывается, сам запуск/история прослушивания записываются
  проигрывателем обычным способом. Дополнительного recording started нет.
- История только в памяти сеанса, очищается при dispose, не меняет schema 9
  и не расширяет постоянные таблицы статистики. Режим disable Wave по-прежнему
  запрещает автоматическое продолжение, даже при наличии будущих визитов.

## Предзагрузка и жизненный цикл

`_NextSelectionSnapshot` содержит прежний QueueState и числовую ревизию истории.
Переход по истории/добавление/очистка меняют ревизию. Это существенно при повторе
того же ID: currentTrack сам по себе не различает два визита одной песни.
Задержанный результат подбора не может заменить план другой позиции истории.

`_buildNextPlan` после проверки ручной очереди подготавливает следующий
сохранённый визит. Перед commit запись проверяется снова: удаление между
предзагрузкой и Next не возвращает устаревшую строку. Если вся будущая часть
пропала, снова выбирается свежая рекомендация. На Back старые недоступные
записи пропускаются в обратном направлении без бесконечного поиска.

Поиск истории ограничен шестью записями и входит в прежний operation tracker.
Ревизия проверяется после каждого DB await: новая ручная сессия/close отменяют
продолжение старой команды. SQLite остаётся открытой до drain, как в пакете 15.
Нативное закрытие процесса и фон Android этим изменением не реализуются.

## Проверки

`wave_history_navigation_test.dart` проверяет 27 сценариев через настоящую
in-memory SQLite, общий проигрыватель и искусственные движки: файлы и URI,
пять шагов/границу/возврат, порог, сбросы, очередь, изменённые теги/лайк,
удалённые/пропавшие записи, отказы, disable Wave, гонку ручного выбора/close,
предзагрузку/crossfade и повтор одного ID. Дополнительный тест общей очереди
проверяет сохранение начального визита при нефатальной ошибке статистики.
Прежние тесты очереди, repeat/shuffle, восстановления источников и lifecycle
выполняются вместе с ними; аппаратный Android-декодер проверяется пользователем
по точечному чек-листу нового APK.
