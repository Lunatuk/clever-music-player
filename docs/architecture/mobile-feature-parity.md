# Мобильный функционал и дизайн

24 октября 2026. Пакет60 проверен пользователем; пакет61 открывает этот блок.
Основной алгоритм рекомендаций остаётся прежним. Расписание загрузок идёт после
основного мобильного интерфейса. Полное переписывание приложения не требуется:
хранилище, очередь, рекомендации и загрузки уже имеют общие сервисы.

## Инвентаризация

| Область | Windows | Android после61 | Следующая работа |
| --- | --- | --- | --- |
| Локальные папки, обновление, отмена | Есть | SAF, сохранённые корни, скрытие удалённых, защита от повторных grants | Встроить в выбранную навигацию |
| Список, обложки, поиск, сортировка | Есть | Ленивый список; поиск по названию/исполнителю/альбому/имени файла, четыре сортировки | Избранное, пользовательские фильтры |
| Воспроизведение, предзагрузка, переходы | Есть | Общий сервис, мини-плеер, фон/уведомление/гарнитура | Полный экран, доступ к параметрам перехода |
| Оценки и история | Есть | Записывается история воспроизведения; UI оценок отсутствует | Лайк/дизлайк и избранное через существующий repository |
| Плейлисты | CRUD, состав/порядок | Общая БД готова, мобильного экрана нет | Список, создание/переименование/удаление, добавление треков, порядок |
| Очередь | Есть | Общая очередь работает, отдельного редактора нет | «Следующим»/«в конец», удаление/перестановка, экран очереди |
| «Волна» | Режимы/настройки | Автоподбор и пять шагов назад; отдельного экрана нет | Показать существующие режимы и настройки |
| Метаданные и обложки | Ручной редактор | Чтение и импорт есть, редактора нет | Мобильный редактор пользовательских правок |

| Диагностика | Отчёт и папка | Сохранение отчёта через системный выбор файла | Общие понятные состояния ошибки/повтора |
| Редизайн | Текущее оформление | Текущее оформление + отдельная демо-галерея61 | Выбрать направление и внедрить реальные экраны |

Точки переиспользования: `queue/playback_queue_service.dart`,
`domain/repositories/playlist_repository.dart`, `track_user_state_repository.dart`,
`data/repositories/drift_repositories.dart`, `library/library_track_list.dart`,
`ui/track_metadata_edit_dialog.dart` и сервисы `library_sync/`.
Desktop-виджеты не копируются целиком в телефон: общими становятся команды,
представления данных и компоненты, компоновка адаптируется под экран.

## Последовательность пакетов

1. **61 — готово к проверке:** поиск/сортировка на настоящей Android-библиотеке;
   три интерактивных направления A/B/C для медиатеки/плеера/очереди на телефоне
   и desktop; эта инвентаризация. Выбор направления предшествует общему редизайну.
2. **62:** выбранная тема и мобильная навигация, избранное и лайки/дизлайки.
   До записи оценок определить поведение нескольких URI одного SAF-документа:
   перенос видимого представителя не должен терять оценки/историю. Существующие
   ID/загрузочные receipts не удалять и не сливать по названиям. Нужны тесты
   отключения корней в обоих порядках, перезапуска и прежних данных.
3. **63:** реальные плейлисты, управление очередью и полный экран трека;
   использовать общую очередь/БД. Проверить перестановки, удаление текущего,
   переход на границе списка, фон и обновление подписок.
4. **64:** прежние режимы «Волны», настройки воспроизведения/переходов,
   недостающие настройки и редактор метаданных/обложек; сохранить имеющееся
   поведение истории, ручных правок и доступа к документам.
5. **65:** согласовать Windows с выбранными темами/компонентами, довести
   адаптивность/доступность и оставшиеся мобильные пробелы; квалификация на
   Redmi и Windows. Объём одного пункта может потребовать отдельных пакетов.

Это порядок работ, не обещание календарных сроков. На каждом пакете — проверки
его контрактов, полный Flutter-набор, анализ/форматирование; для Android — JVM,
lint и проверка фактического APK. Пользователю выдаётся короткая проверка только
изменившегося поведения. После блока — расписание обновлений, Android background
download lifecycle и оставшиеся пункты общего roadmap.

## Границы61

`buildVisibleLibraryTracks` определяет видимый список и контекст запуска.
Поиск/сортировка живут в состоянии экрана, не записываются в БД и не меняют уже
запущенную очередь. После закрытия приложения запрос очищается, сортировка
возвращается к названию. При открытой клавиатуре мини-плеер скрывается ради
места, воспроизведение продолжается; в landscape транспорт компактен.

`ui/design_preview/` работает только с вымышленными данными, собственными
рисованными обложками и локальным состоянием виджетов. Демо открывается через
«О версии» → «Варианты дизайна»; его кнопки не управляют реальной музыкой, БД,
Яндексом или файлами. Это сравнение композиции, ещё не перенос всех функций.
Направления: A «Графит» — зелёная тёмная тема и плотный список;
B «Бумага» — светлая тема и альбомная сетка;
C «Полночь» — синяя тёмная тема и боковая очередь на desktop.

Снимки экспортируются непосредственно Flutter-тестом при
`CMP_EXPORT_DESIGN_PREVIEW=<directory>`; `tool/package_design_preview.py` создаёт
автономный HTML из18 снимков с переключением устройства/экрана и увеличением.
Segoe UI используется только в Windows-экспорте; Android использует системный
шрифт. Проверяются обычный phone/desktop, узкий320px, текст200%, контраст и
локальные действия. Физическая проверка61 на Redmi ещё нужна.
