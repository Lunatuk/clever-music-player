# Пакет 39 — диагностика подключения к Яндексу

Пакет40 изменяет порядок входа и каталог: verified credential сохраняется до
discovery, объединяются свои и сохранённые плейлисты, optional labels/counts
не блокируют вход. Ниже зафиксирован контракт соответствующего прежнего пакета;
актуальные отличия описаны в [пакете40](yandex-playlist-catalogue.md).

Пользователь сообщил тайм-аут в пакете 38, затем повторил вход со свежим токеном
без VPN с тем же результатом. В двух предоставленных отчётах последняя сессия
содержит только startup/database/media/ready: обработанные ошибки Яндекса
до пакета 39 вообще не регистрировались. Это исправление наблюдаемости,
а не подтверждение устранения причины входа. Настоящая авторизация не проверена.

Во время первого исследования даже curl без токена не устанавливал TCP к API,
хотя сайт открывался. Во время следующего исследования тот же адрес ответил
HTTP 200 примерно за 2–3 секунды через curl и штатный Dart HttpClient без токена.
Разница не доказывает виновность VPN, валидность токена или работоспособность
запроса плейлистов. Это разные моменты времени и разные процессы относительно
плеера. Следующее решение принимается по отчёту из самого приложения.

## Поведение

- «Проверить соединение» явно делает GET `/account/status` через тот же
  фиксированный HTTPS origin, ограничения времени/размера и TLS transport.
  Проба не читает credential store/SQLite, не получает токен и не добавляет
  Authorization/Cookie. Результат не является проверкой аккаунта или подписки.
- HTTP 200 с корректным result либо unauthorized envelope, а также HTTP 401
  подтверждают доступность API без авторизации. Redirect/HTML/неполный ответ
  не принимаются за успех. 403/429 показывают соответствующую ошибку.
- Ошибка или отмена пробы сохраняет существующее подключение, credential и
  состав коллекций. Закрытие сервиса отменяет/дожидается пробы и закрывает её
  transport до SQLite. Уход с экрана отменяет принятую операцию.
- Вход сохраняет прежнюю последовательность: проверка аккаунта → собственные
  плейлисты → короткая запись credential/DB. Каждый шаг теперь виден в UI.
  Автоматические retry, увеличение тайм-аутов, обход VPN, смена DNS/прокси или
  отключение проверки сертификата не добавляются.
- Ошибки переносят типизированный этап через client/refresher/controller.
  Тайм-аут подключения отличается от ожидания ответа, неполного тела и decode.
  Native TimeoutException также классифицируется как timeout, а не network.

## Журнал

Только enum коды, конечные числа и booleans проходят прежний whitelist.
Нет URL, UID, названий, секретов, заголовков, сырых ошибок/ответов или stack trace.
`credentialAttached` означает установку OAuth заголовка после открытия
соединения; это не доказательство доставки заголовка серверу. До этой точки,
при ошибке соединения и у пробы значение false. `responseBytes` — полученные
декодированные из HTTP compression байты, не объём wire traffic.

| События | Поля |
| --- | --- |
| yandexRequestStarted / Completed / Failed | remoteEndpoint, remoteStage, elapsedMs, responseBytes, credentialAttached; httpStatus после ответа; remoteFailure/числовой networkErrorCode при ошибке |
| yandexOperationStarted / Completed / Failed | remoteOperation, elapsedMs при завершении; remoteConnectionFailure и remoteStage при ошибке |

Коды:

- `remoteEndpoint`: 0 account, 1 playlists, 2 likedTracks, 3 playlist.
- `remoteStage`: 0 connecting (DNS/TCP/TLS вместе), 1 waitingForResponse,
  2 receivingBody, 3 decoding. Это последний достигнутый этап, не отдельный
  детальный TCP trace. Например, HTTP 401 зарегистрирован на receivingBody.
- `remoteOperation`: 0 idle, 1 restoring, 2 connecting, 3 catalogue,
  4 checking, 5 selecting, 6 disconnecting, 7 probing.
- `remoteFailure`: индекс YandexLibraryFailure из протокола; это отдельная
  шкала от `remoteConnectionFailure` — индекса YandexConnectionFailure UI.
  Существующие значения нельзя переупорядочивать; новые добавляются в конец.

Обычные запуск/воспроизведение/сканирование не вызывают пробу или API.
Ни сетевой origin/права Android, ни зависимости, ни схема 13 не меняются.

## Проверки и следующий шаг

20 новых тестов: 10 с настоящими loopback HTTP/экспортом локального отчёта,
6 контроллера, 4 widget. Проверяются отсутствие Authorization на пробе,
401/unauthorized/redirect, header/body timeout, числовая OS ошибка при закрытом
порту, decode и отсутствие секретов в фактическом JSON отчёте. Проверены
сохранность активного входа, cancel/close, прогресс плейлистов и разные ошибки UI.
Автоматизация использует синтетические credentials и временные БД/каталоги.
Реальные секреты пользователя не читались, не пересылались и в тесты не входят.

По [чек-листу](../MANUAL_CHECKS.md) достаточно нажать пробу, один раз повторить
вход и экспортировать отчёт. До выяснения причины следующий download этап
остаётся отложенным. Сквозная ручная проверка пакета 38 пока не подтверждена.
