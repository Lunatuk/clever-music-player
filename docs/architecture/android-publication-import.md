# Android: подтверждённый документ и атомарный импорт (пакет 54)

Продолжение в55: [физический publisher и проверка записи](android-audio-publication.md).
Ниже зафиксировано состояние внутреннего импорта на момент54.

Пользователь подтвердил SAF-проверку пакета53 на телефоне. Пакет54 добавляет
внутренний путь от уже подготовленного/записанного документа до общей БД.
Скачивание песен на Android не включается. Интерфейс53 остаётся прежним;
новая физическая запись, теги/обложки и подключение runner ещё впереди.

## Общая модель назначения

`DocumentPublicationLocation` связывает выбранный tree URI, документ и имя,
которое фактически вернул provider. Проверяются authority/tree ID, структура
URI, отсутствие query/fragment/NUL и принадлежность документа другому ID,
чем корень. Document ID остаётся непрозрачным: из него не извлекается путь
или имя. Структура URI сама по себе не доказывает членство в каталоге;
для этого требуется отдельная проверка Android-поставщика.

`DownloadedTrackImport` принимает content URI только вместе с таким
подтверждением и точным ожидаемым именем публикации. Для файловых источников
подтверждение документа запрещено; прежнее правило полного пути сохраняется.
Единый `publicationSourceMatchesDestination` связывает подготовленный
источник с текущим адресом папки при commit, acknowledgement replay и cleanup.
Content URI нигде не проходит через `path.join/absolute/normalize`.

SQLite по-прежнему одной транзакцией записывает Track, внешний ID, проверенный
asset и завершение попытки. Сохраняются полный CAS, lease, account revision,
enabled folder, откат всех записей и сохранение ручных правок при replay.
Схема13 прежняя; никаких сетевых запросов или provider IO внутри транзакции.

## Проверка текущего документа

Новый read-only канал `publication_verifier` проверяет оба persisted grants,
доступность корня, прямое членство документа и точное display name. Он читает
полный файл ограниченным SHA-256 reader, закрывает поток, затем повторно
проверяет членство/имя/размер/mtime. Размер может быть неизвестен provider:
в этом случае всё равно обязательны точное число прочитанных байтов и хэш.
Лимит8ГиБ, буфер64КиБ, максимум16нулевых чтений, обход до10000документов.
Возвращаются только фиксированный статус, request ID и ожидаемые bytes/hash;
пути и тексты исключений не возвращаются. Нет скачивания/декодирования/записи.

Worker отдельный; отмена использует CancellationSignal/PFD close через bounded
executor. Dart close ждёт фактического окончания принятого чтения. Зависший
provider не получает выдуманный hard timeout с продолжающимся фоновым IO.
Проверка даёт подтверждение на момент чтения, а не постоянную блокировку
внешних изменений файла. Это не квалификация аудиокодека или тегов.

## Долговечный результат

`AndroidPublicationReceipt` содержит прежний строгий PublicationIntent
(job/key/publication ID и аудио/байтовое подтверждение) и location документа.
Кодек version1 канонический, максимум65536байт; лишние поля/другая версия/
повреждённые URI/подмена имени отвергаются. Старый receipt не подтверждает,
что файл всё ещё существует и содержит те же байты.

`AndroidPublicationJournal` открывается явно в app-private обычных файлах:
`android-downloads/publication-receipts-v1`. Отдельный owner marker, OS lock,
проверка путей/типов, immutable records через flush + moveNoReplace; SAF URI
не передаются файловым системным вызовам. Новый record принимается только
под коротким `withOwnedDestination` с тем же tree URI. Повтор ровно того же
record — чтение, не доказательство текущего владения. Перепривязка ID к другому
документу запрещена. До512записей по64КиБ; известные прерванные journal-*.part
не становятся receipts и учитываются в квоте. Неизвестные/повреждённые записи
сохраняются и блокируют мутацию. Close дренирует принятые записи перед unlock.

Журнал не содержит OAuth и не экспортируется диагностикой. Он хранит URI и
точные ID внутри приложения. Полные музыкальные файлы туда не копируются.
Это журнал уже завершённого provider write; intent/create/write/rename до
receipt ещё должен реализовать будущий физический SAF publisher. Он обязан
записывать intent до create и URI до write, не теряя неоднозначные результаты.

## Импорт и восстановление

`AndroidPublicationImporter` получает уже подготовленные метаданные и receipt,
сохраняет receipt, повторно проверяет реальный документ и только затем делает
общий atomic commit. `DownloadLeaseOwner` продлевает попытку во время provider
IO; чтение не держит его serial gate или SQLite writer. Коммит использует
актуальную ревизию того же owner. Потеря аккаунта/папки/lease не даёт частично
импортировать трек. Старый receipt после рестарта требует новой физической
проверки и подтверждения в текущей попытке; checkpoint сам не означает успех.

После commit отдельная cleanup authority сверяет completed job, enabled folder,
URI, publication ID и проверенный asset. Только тогда удаляется приватный
receipt. При отказе он остаётся; completed не превращается в новый download.
Код этой очистки не удаляет музыкальный документ. Desktop abandoned cleanup
не получает Android tree URI вместо файлового пути: для незавершённой
SAF-публикации потребуется отдельная политика очистки.

## Проверки и оставшиеся границы

Flutter tests используют настоящий SQLite и native no-replace/OS locks для
приватного журнала. Проверяются атомарный импорт opaque URI, все фазы отката,
stale/session/folder/grants evidence, replay/manual metadata, квоты/повреждение,
рестарт persistent DB + receipt + новая попытка, heartbeat во время readback,
cancel/close/drain и потеря cleanup authority после успешного commit.
JVM tests проверяют полный readback/close, размеры/hash/mtime, смену членства,
ошибки прав/закрытия, отмену и лимиты независимого verifier core.

Реальный ContentResolver в этих тестах не заменяется утверждением об успешной
проверке на телефоне. Новый канал ещё не связан с публичным скачиванием;
проверка53, которую подтвердил пользователь, не квалифицирует новый verifier.
App-owned создание importer/journal и маршрутизация настоящих заданий появятся
вместе с физическим SAF publisher/Android metadata backend. До этого нового
ручного теста нет; APK54 — сборка для проверки совместимости, установка необязательна.
