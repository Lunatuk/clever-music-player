# Физическая проверка зарегистрированного ресурса

Пакет 29, схема 13. `DownloadedAssetChecker` получает полный снимок
`DownloadedAsset` и читает ресурс через `SourceFingerprintProbe`.
Проверяется доступ, полный SHA-256 и размер. Название, расширение и теги
не заменяют проверку байтов; файл такого же размера с другим содержимым
считается изменённым. Исходные файлы не записываются и не удаляются.

Это проверка повторного использования ранее проверенного файла. Совпадение
всех байтов связывает прежние сведения о контейнере/кодеке/качестве/длительности
с прочитанным содержимым. Сервис не определяет эти свойства заново,
не декодирует аудио и не объявляет новый скачанный файл исправным.
Валидатор новых файлов после записи тегов/обложки остаётся отдельной задачей.

| Результат чтения | Изменение реестра |
| --- | --- |
| Размер и полный SHA-256 совпали | CAS confirm, новое UTC-время проверки |
| Другие байты/размер, нестабильное чтение | CAS invalid |
| Файл не найден | CAS missing |
| Отказ доступа/нет постоянного SAF grant | CAS accessDenied |
| Ошибка провайдера/занятый файл/неподдерживаемый источник/протокол | unreadable, прежняя запись сохранена |
| Отмена до принятия CAS | cancelled, без записи |
| CAS отказал по снимку/связям/времени | stale, новая запись не перезаписывается |

CAS использует существующий репозиторий и полный снимок публикации, ревизии,
состояния и доказательства. Ошибки SQLite распространяются вызывающему коду;
они не маскируются результатом чтения. Восстановившийся файл можно проверить
по актуальному missing/accessDenied-снимку, если прежние байты снова доступны.
При изменении результата будущий координатор должен заново получить план.
Только confirmed разрешает переиспользование в текущей операции; unreadable
сохраняет прежнюю запись, но не разрешает пропустить загрузку или проверку.
Успех проверки не равен выполнению всего задания или сетевой синхронизации.

На Windows/macOS `FileSourceFingerprintProbe` использует существующий
`Sha256HashSession`: один ленивый isolate, постоянный ограниченный буфер,
Windows CNG с прежним Dart fallback. Проверяются размер/даты до и после
чтения. Типизированный `FileContentChangedException` остаётся
`FileSystemException`, сохраняя контракт сканера. Обычные ошибки ОС
различаются по кодам, без разбора текста. Если stat скрыл причину,
read-only open восстанавливает код; успешное открытие после неоднозначной
ошибки не даёт основания объявлять файл отсутствующим.

На Android отдельный `AudioFingerprintPlugin` использует собственный поток,
не занимая рабочий поток просмотра папок/метаданных. Один активный запрос,
отказ busy вместо очереди, буфер 64 КиБ, Java SHA-256; музыка не копируется
во временный файл. `openAssetFileDescriptor` и `createInputStream` сохраняют
поддержку поддиапазонов файлов у провайдера. Использование `openFileDescriptor`
вместо него могло бы давать FileNotFound для таких провайдеров.
См. [контракт ContentResolver](https://developer.android.com/reference/android/content/ContentResolver).

Доступ проверяется по постоянным grants для отдельного документа или того же
SAF tree, как в текущем импорте. Это адаптер текущих SAF-источников;
MediaStore с общими разрешениями потребует отдельной политики доступа.
Размер/last_modified запрашиваются до/после; неизвестные метаданные допустимы,
если прочитаны все ожидаемые байты. Несовпадающий известный размер и более
длинный поток останавливают чтение. Шестнадцать пустых чтений подряд дают
ошибку вместо бесконечного цикла. При FileNotFound grant проверяется повторно,
чтобы отзыв разрешения не записался как missing. SecurityException отличается
от остальных сбоев; произвольные сообщения/URI не возвращаются в ошибках.

Канал `audio_fingerprint`: fingerprintAudio(requestId, uri, expectedSize),
cancelAudioFingerprint(requestId). ID — положительное 32-битное целое,
размер — положительное целое. Ответ содержит тот же ID и фиксированный
статус; успешный ответ требует точного ожидаемого размера и canonical SHA-256.
Dart отвергает неизвестные статусы, чужие ID, неправильные типы/хэши.
При отмене ждёт завершения первоначального запроса, не бросает native Future.

Общая отмена использует существующий `LibraryScanControl` как кооперативный
токен; прогресс сканера здесь не публикуется. Таймаут по умолчанию пять минут,
допустим 0 < timeout <= 30 минут. Таймаут отменяет чтение и возвращает unreadable
после освобождения ресурса, не доказывает порчу файла. На Android используются
CancellationSignal и закрытие активного дескриптора вне UI-потока. Очередь
отдельного потока отмены ограничена одним местом, повторные отмены объединяются.
Провайдер может игнорировать отмену/зависнуть внутри собственного вызова:
жёсткого ограничения длительности и принудительного убийства IO нет.

Один сервис проверяет один файл; следующий параллельный запрос отклоняется.
`close` закрывает приём, запрашивает отмену, ждёт чтение и уже принятый CAS,
затем закрывает probe. После принятия CAS результат сообщает фактический
исход записи, даже если пользователь одновременно нажал отмену.
`AppDependencies.assetChecker` создаётся лениво платформенной фабрикой;
его закрытие дренируется до SQLite. Без обращения к сервису загрузки/хэширования
на старте нет. Новый AppResource добавлен в конец enum: прежние числовые
коды диагностики не перенумерованы.

Проверка является снимком прочитанных байтов и обычных метаданных. Она не
устанавливает файловую блокировку и не гарантирует, что внешний процесс
не заменит файл сразу после проверки. Будущей публикации нужны собственные
блокировки назначения, fencing, промежуточные ресурсы и журнал завершения;
одна lease в SQLite не даёт права перезаписывать файл после потери владения.

Автотесты используют временные файлы/SQLite, канальные ответы и чистый JVM
stream helper: совпадение/замена/удаление/возврат, stale revision, регрессия часов,
доступ/IO/протокол, отмена/таймаут/close/busy, дренирование CAS/SQLite,
частичные блоки/короткий/длинный/застрявший поток. Android API пути
компилируются и проходят lint; физический SAF-провайдер/macOS ещё не запускались.
