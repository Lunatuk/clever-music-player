# Доставка аудио и доступное качество

Пакет 48, 19 октября 2026. Уточняет контракт пакетов 43/47.

## Причина отказа

Отчёт пользователя показывал HTTP 200 на метаданные и get-file-info, затем
DownloadFailure.unavailable до начала audio HTTP. Ограниченная живая проверка
на одном уже выбранном задании подтвердила: для MP3, M4A и FLAC-запроса сервер
возвращает nq/192 кбит/с. Аккаунт совпадает с сохранённым подключением, hasPlus
положителен. Старый точный профиль HQ320/lossless отклонял этот ответ.
Смена VPN не исправляет эту проверку качества приложения.

## Запрос и профили

get-file-info теперь использует bare track ID, сохраняя album context в запросе
метаданных и локальной идентичности. Подпись использует тот же ID и encraw;
публичная desktop protocol constant и client header остаются прежними.
Метаданные продолжают проверять track/album/realId, подстановки не принимаются.

MP3 и M4A означают лучшее доступное в этом формате: запрос HQ, допускаются
ответы HQ/NQ с заявленным битрейтом от 128 кбит/с и измеряемым порогом 96 кбит/с.
Меню честно показывает «до 320» и «AAC до 256»; нет обещания повысить качество
кодированием. Фактический формат и полная длительность проверяются helper.
FLAC требует lossless + FLAC; ответ MP3/AAC не переименовывается и не
перекодируется в фиктивный lossless. Недоступный вариант объясняется в UI.
Профили по-прежнему содержат политику проверки в ключе задания. Старые задания
с прежней политикой не переписываются и не получают автоматического повтора.

## Потоковая доставка

Поддерживаются raw и encraw с независимо проверенным доменом strm.yandex.net.
raw допускает отсутствующий/пустой key и требует /music-v2/raw/.
encraw требует hex AES key длиной 16/24/32 байта и /music-v2/crypt/.
Неизвестный transport, неверный ключ, preview и несогласованный путь запрещены.

YandexAudioDecoder использует PointyCastle 4.0.0 (только AES/SIC imports),
AES-CTR с нулевым 16-байтовым IV и начальным counter0, как в SDK и YaDown.
Состояние счётчика сохраняется между HTTP-чанками, включая неполные блоки;
каждый новый поток получает новое состояние. Обработка ограничена блоками
16 KiB с передачей управления event loop и проверкой отмены. В пределах
допущенного размера файла счётчик не достигает границы 32 бит.

Декодированные байты сразу входят в прежнюю RawDownloadReservation: нет второй
копии файла, буфера всей песни или дополнительного расхода workspace.
Длина AES-CTR неизменна, сохраняются Content-Length, quota, backpressure,
idle/total timeout, отмена/закрытие HTTP и владение файлом. OAuth остаётся только
на фиксированном API, CDN получает анонимный запрос. Ключ и подписанные URL
живут в памяти; в журнал, SQLite и настройки не записываются.
Успех транспорта не заменяет проверку аудио: неверно декодированный payload
не проходит helper и не публикуется.

Новые yandexDownloadResolved/Rejected сохраняют только числовые индексы
запрошенного/возвращённого формата, качества, transport, bitrate и кода отказа.
Неизвестные строки превращаются в -1; ошибка диагностики не меняет исход.

## Проверки и границы

Независимые OpenSSL vectors для AES128/192/256 находятся в
test/fixtures/yandex_aes_ctr.json: ключи — искусственные bytes(range(n)),
IV — нулевой, plain — bytes(range(113)). Это публичные тестовые данные.
Проверяются фрагментация блоков, повтор потока, отмена и ограниченный размер.
Нативный synthetic HTTP/helper/SQLite pipeline проверяет MP3/M4A/FLAC encraw,
NQ192 fallback для lossy, теги/обложку/импорт/повтор, отмену с повтором и отказ
при неверном ключе без публикации. UI использует общую production theme;
геометрический тест пустой папки исключает пересечение label/hint.

Живые MP3 и M4A одного выбранного трека скачаны только во временные папки,
проверены qualified FFprobe и полным FFmpeg decode, затем удалены. Пользовательская
SQLite открывалась read-only, защищённое подключение читалось через штатный
backend без миграции/записи; библиотека и выбор не менялись. В логах только
технические числа и флаги. Это не подтверждение живого UI-импорта или FLAC
для каталога: проверенный трек сервер отдавал только в NQ192.
Android download/SAF и macOS qualification остаются отдельными этапами.
