# Внешние ID треков, пакет 24

Внутренний Tracks.id остаётся владельцем оценок, истории, плейлистов и обложек.
ExternalTrackIdentity описывает объект провайдера отдельно: provider, externalId,
variantKey. Для будущего адаптера Яндекса зарезервировано имя yandex_music;
контекст версии/альбома определяет сам адаптер. Это не путь, имя трека или
хэш аудио. Пример: yandex_music / 12345 / album:67890.

ID и контекст непрозрачны: регистр, ведущие нули и специальные символы сохраняются.
Provider — lowercase ASCII namespace до 64 символов. ID/контекст ограничены
512 символами, управляющие символы запрещены; ID непустой. Пустой variantKey
означает отсутствие контекста и отличается от конкретной версии. NULL вместо
него не используется, чтобы повтор ссылки имел однозначную уникальность.

ExternalTrackRef связывает идентичность с сохранённым trackId, происхождением
и временем первого добавления. Происхождение: embeddedTag, providerResponse,
manual. Более сильное подтверждение может повысить источник связи, повторный
импорт не понижает его. Время первого добавления сохраняется. Предположения по
названию/исполнителю сюда не записываются. Ссылка не доказывает, что аудиофайл
скачан, доступен или проверен: это будущая ответственность DownloadedAsset.

## Хранение и контракты

Схема 10 добавляет external_track_refs с составным первичным ключом
(track_id, provider, external_id, variant_key), FK к tracks с ON DELETE CASCADE
и индексом поиска (provider, external_id, variant_key, track_id). Глобальной
уникальности внешнего ID нет: несколько независимых локальных копий могут
относиться к одному объекту. Разные providers/версии/ID не смешиваются.

AppRepositories.externalTracks доступен общей логике Windows/macOS/Android.
ExternalTrackRepository.linkAll принимает до 64 связей одной транзакцией:

- Снимок входа формируется до async; повторы одного ключа внутри пакета
  сводятся к одной связи с наиболее сильным происхождением.
- Наличие всех локальных треков проверяется в той же транзакции. Отсутствующий
  ID отменяет пакет целиком. Ошибка SQLite откатывает вставки и повышения.
- Повтор уже сохранённой ссылки не создаёт записи и не меняет время связи.
  Метаданные, файлы и пользовательские таблицы не затрагиваются.

findRefs возвращает все точные связи, включая недоступные/отключённые копии.
Планировщик загрузок должен отдельно проверить конкретный ресурс/качество/
состояние; нельзя считать первый результат единственным готовым файлом.
listForTrack показывает связи записи, unlink удаляет только одну связь.
Сортировка детерминирована, возвращаемые списки неизменяемы.

DriftTrackRepository удаляет внешние связи явно внутри своих транзакций удаления
трека/владельца. Это согласовано с прежними ручными очистками дочерних таблиц и
работает также с отключённым SQLite foreign_keys. При ошибке удаления связи
восстанавливаются вместе с записью. Отключение папки и сброс обучения сохраняют
связи; редактирование тегов/custom cover и повторный импорт тоже сохраняют их.

## Миграция и границы

Переход 1–9 → 10 создаёт таблицу/индекс без перестройки старых таблиц. Новые
связи первоначально пусты; ID не угадываются из названий или адресов. DDL и
user_version коммитятся вместе. Сбой создания таблиц/индексов/версии откатывается;
следующий запуск повторяет миграцию. Проверки сравнивают значения прежних строк,
внешние ключи и integrity_check. Замороженная test/fixtures/schema_v9.sql
фиксирует схему пакетов 19–23; личные данные в тестах не используются.

Аккаунт/токен, удалённые коллекции и их порядок, статусы заданий, публикация
файлов, качество/проверка DownloadedAsset, несколько жанров, алиасы Android URI
и сетевой адаптер остаются следующими этапами. Привязки каталога провайдера не
заменяют принадлежность коллекциям конкретного аккаунта и локальные лайки.
Новых технических полей ввода в интерфейсе пользователя нет.


## Проверки

22 новых модельных/SQLite-сценария: валидация и точность ID, копии/версии,
происхождение/время первого добавления, повторы/конкуренция/пакет 64, отсутствующий
трек и SQLite-trigger rollback, сохранность ручных тегов/обложки/истории/списков,
редактирование/повторный импорт, скрытые источники, очистка при удалении и её
откат, индексированный поиск, повторное открытие файловой SQLite.

11 новых сценариев миграции дополняют прежние проверки: схема 9, Android URI/
владение/жанровая строка/настройки/данные, дополнительные точки отката для схем
1/7/8/9 и откат первой установки. Все схемы 1–9 сверяются без изменения прежних
строк. Полный прогон: 826 Flutter-тестов, 6 JVM-тестов обхода Android, нативный
Windows-аудиопротокол, release APK/Windows ZIP. macOS в этой Windows-сессии
не собирался; соответствующая CI-задача остаётся в репозитории.
