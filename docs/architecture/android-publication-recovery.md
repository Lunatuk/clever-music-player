# Android: решения восстановления публикации

Пакет57, 23 октября 2026 года. Проверка56 на телефоне подтверждена пользователем.
Это следующий внутренний шаг перед реальным Android-download pipeline; кнопка
скачивания ещё не включена. Схема13, credential/network и Windows pipeline прежние.

## Решение для текущей попытки

`AndroidAudioPublisher.recover` принимает только текущую claimed попытку в
`reconciling`. В одном publisher admission она объединяет native ledger55 и
Dart receipts54. После чтения повторно проверяется текущее владение/назначение.
Чужие job/key не принимаются, одинаковые ID с разными intent отклоняются.

* Нет записей: `requiresDownload`. Публикация требует durable intent до эффекта,
  поэтому отсутствие обоих журналов не подтверждает прежнюю готовую запись.
* Одна запись INTENT без последующих фаз и без Dart receipt: native
  `releaseUncreatedAudioPublication` под текущим SQLite/lease/destination fence
  освобождает только приватный intent, возвращает привязанные intent bytes/stage.
  Provider не вызывается. Старый ожидающий publish уже не найдёт своё admission.
* CREATING/DOCUMENT/READY не освобождаются этим методом. После отказа
  `needsReconciliation` запускается прежняя read-only сверка документа вне DB
  fence; полный SHA-256/размер/close/stamps/grants/parent/name обязательны.
  Готовый документ становится `published`, receipt сохраняется до native ack.
* Receipt без native ledger повторно проверяется через verifier54, без raw-файла.
* Частичный/изменённый документ, неоднозначный create, потеря доступа и несколько
  кандидатов дают `retained` с фиксированным кодом. Ни write, ни delete музыки,
  ни разрешения повторного скачивания нет. Пустой CREATING тоже неоднозначен:
  отсутствие по одному имени не доказывает отсутствие файла после переименования.
* Неизвестная ошибка/повреждённый журнал/потеря владельца/отмена не превращаются
  в разрешение нового download. Принятый private-only release дренируется при
  close; готовый native result сначала сохраняется в receipt.

Результат не меняет checkpoint очереди и не импортирует Track. Будущий координатор
должен consume `requiresDownload` через `owner.resolve(download)` либо принять
receipt и закончить импорт54 под текущим owner. При `retained` требуется отдельное
понятное сообщение/разрешение ситуации; автоматической очистки музыки нет.
Политика удаления/дописывания частичных песен не введена. Подменять `retained`
автоматическим retry, очищать журнал или отключать quarantine нельзя.

## Явная проверка на телефоне

Прежняя проверка записи55 остаётся первым шагом: app-private источник → native
publisher → полный readback → удаление только известного nonce-marked probe.
Затем `AudioPublicationRecoveryCheck` последовательно проверяет ещё три случая:

1. INTENT до create: освобождение другим owner без обращения к provider.
2. Полная запись с закрытыми потоками, но прерывание до readback/READY:
   новый read-only adapter проверяет bytes и восстанавливает READY без source.
3. Прерывание после первых2048байт из4096: read-only recovery отклоняет неполное
   содержимое, READY отсутствует. Удаляется только свой известный probe с
   совпадающим nonce prefix; музыка никогда не проходит эту ветку cleanup.

Каждый случай имеет новый случайный ID. Ошибки/отмена дренируют потоки; неполная
очистка остаётся в прежнем журнале и сообщает `retained`. Проверка не запускается
автоматически, не обращается к аккаунту/сети и не проигрывает тестовые звуки.
Это контролируемые прерывания в живом процессе, не эмуляция смерти процесса,
потери питания, утраты данных в provider или полного диска.

Native ответ `ready` требует `recoveryChecks=3`; Dart отвергает отсутствующее,
неполное/противоречивое подтверждение. Legacy probe53 сохраняет старый протокол.
Диагностика добавляет только числовое `publicationRecoveryChecks`; пути, URI,
имена и содержимое файлов не попадают в отчёт.

## Проверки и границы

JVM tests проверяют запрет release после каждого возможного эффекта, старый
writer, несовпадение binding, три recovery сценария, закрытие потоков и cleanup.
Flutter tests используют настоящий SQLite/lease/receipt journal с fake provider:
новая попытка, source-free recovery, revoked session, multiple candidates,
изменённые bytes, неисправный ответ, cancellation/drain и numeric diagnostics.
Реальный ContentResolver квалифицируется пользователем через APK57 на Redmi.

Далее: Android coordinator с preparer56/publisher55/recovery57/importer54,
общий session-bound runner и явное обновление маленькой коллекции. Усложнение
рекомендаций отложено; расписание и дизайн после ручного скачивания.

Автоматическая квалификация57: 2284 Flutter tests (30 новых), 108 targeted,
анализатор без замечаний; 84 JVM tests, lint0errors/9 прежних warnings.
Итоговый APK2057 с подписью56 и16КиБ проверен отдельно. Итоговые числа и SHA записаны в IMPLEMENTATION_LOG.md и checks JSON.
