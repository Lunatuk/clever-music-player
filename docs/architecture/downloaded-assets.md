# Учёт скачанных ресурсов, пакет 25

ExternalTrackRef подтверждает связь с объектом каталога. DownloadedAsset
хранит сведения о конкретном завершённом локальном файле отдельно от этой
связи. Временные файлы и этапы загрузки принадлежат будущим заданиям, а не
библиотеке готовых ресурсов. Реестр не скачивает и не проверяет аудио сам.

## Публикация и подтверждение

DownloadedAssetPublication содержит trackId, точную внешнюю идентичность,
адрес файла/content URI, ID публикации и запрошенное качество.
ID публикации — ограниченный токен, не подписанная ссылка и не путь. Новая
публикация получает новый токен, повтор её команды использует прежний.

DownloadedAssetVerification сообщает фактическое качество, container/codec,
положительные размер/длительность, SHA-256 окончательного файла после записи
тегов/обложки и UTC-время проверки. Метки качества непрозрачны, их значения
определяет адаптер. Формат — нормализованный lowercase код. Расширение файла
не участвует в определении формата. Время хранится в микросекундах, длительность
в миллисекундах; повторное чтение не теряет точность снимка.

registerVerified требует уже существующие Track и точный ExternalTrackRef.
Источник должен совпадать с текущим адресом трека, известные размер/hash —
с подтверждением. Операция не меняет теги, пользовательские данные или файлы.
У одного trackId один текущий ресурс, у разных локальных копий — отдельные.
Активные ID публикаций уникальны.

Повтор того же токена и неизменных данных возвращает прежнюю запись, включая
состояние, ревизию и первое подтверждение. Повтор с другими свойствами
отклоняется. Он не восстанавливает отсутствующий файл автоматически. Для новой
публикации нужны новый токен и актуальный заменяемый снимок; внешняя музыкальная
идентичность сохраняется, чтобы улучшение качества не подменяло другой трек.

## Состояния и запоздалые результаты

Состояния: verified, missing, accessDenied, invalid. Последнее подтверждение
сохраняется и при недоступности. Ревизия растёт при изменениях. invalidate и
confirm принимают снимок, с которым началась операция, и сравнивают его целиком
с текущим. Устаревший результат возвращает false без записи. Это защищает и от
удаления/повторного создания записи со случайно повторённым токеном, если её
данные уже изменились.

confirm дополнительно требует прежние свойства/байты, непротиворечивый текущий
Track и время проверки не старше сохранённого. Изменённые байты регистрируются
новой публикацией. Статус verified нельзя поставить через invalidate.
Повторы уже достигнутого состояния не создают лишних ревизий.

## Кандидаты для повторного использования

findCandidates сопоставляет provider/ID/контекст, фактическое качество и точный
libraryFolderId назначения; null означает только отдельные файлы без владельца.
Копия из другого каталога не выдаётся за файл нужного назначения. Выбираются
verified-ресурсы с непропавшим Track, включённым источником, текущим URI/путём
и совместимыми известными размером/hash. findForTrack показывает и недоступные
состояния для диагностики/восстановления.

Запрошенный lossless с фактическим high сохраняет оба значения и не удовлетворяет
запросу lossless. Он может быть кандидатом для запроса high. Сравнение качества
точное; политика допустимых замен будет частью планировщика.

Результат SQL — только кандидат: после последней проверки файл/разрешение могли
измениться. Будущий координатор обязан проверить актуальное состояние ОС/файла
до пропуска загрузки или использования ресурса. Старые внешние ссылки не
превращаются в готовые загрузки по факту наличия ID или похожего имени.

## SQLite и удаление

Схема 11 добавляет downloaded_assets, индекс идентичности/качества/состояния,
уникальность publication_id, PK/FK track_id и составной FK к external_track_refs.
Миграция 1–10 не перестраивает прежние таблицы и не читает аудиофайлы. Схема 10
зафиксирована в test/fixtures/schema_v10.sql; прежние значения/ID/связи сохраняются.
DDL и номер версии откатываются совместно при сбое.

Удаление трека/его владельца очищает ресурсы и ссылки одной транзакцией. Снятие
точной внешней связи очищает её ресурс; другая связь не затрагивается. Файлы,
локальная музыкальная запись и пользовательские данные при unlink сохраняются.
Очистка выполняется явно также с прежним foreign_keys=off; составной CASCADE
дополнительно проверен с включённым enforcement. Ошибки SQLite откатывают результат.
Отключение источника, изменение тегов/обложки и сброс обучения не удаляют учёт.

Аккаунты/коллекции, устойчивые задания и публикация файлов, физический verifier,
сетевая авторизация/загрузка, несколько жанров и алиасы источников остаются
следующими этапами. Будущий координатор должен также владеть отменой/завершением
заданий и дренировать принятые записи до закрытия общей SQLite.
