# Ручное обновление библиотеки из Яндекс Музыки

Пакет 47, 19 октября 2026. Первая доступная в интерфейсе загрузка — Windows x64.
Android сохраняет подключение аккаунта, выбор и проверку коллекций; скачивание
на Android требует отдельной реализации private workspace/SAF/тегов.

## Владение и настройки

AppDependencies лениво создаёт один YandexLibraryUpdateController. Конструктор
не читает credential и не запускает helper, сеть или файловый worker.
Открытие настроек читает только параметры назначения и список включённых папок.
Папка выбирается явно из библиотеки. Настройки версии 1 сохраняют ID папки,
качество и лимит; путей и секретов в значении нет. Ошибка записи сохраняет
предыдущее значение и в контроллере, и в выпадающем списке.

Доступны MP3 HQ с объявленным битрейтом не ниже 320 кбит/с и проверяемым
фактическим битрейтом, либо FLAC без потерь. Тихого понижения качества нет.
Лимиты — 3 (по умолчанию), 10, 50 или все задания в пределах ограничения
снимка 100000. Лимит ограничивает попытки runner, а не размер сохранённого плана.
Оставшиеся задания не запускаются сами. Повтор failed/cancelled разрешается
только явным флажком; при первом отказе текущий запуск останавливается.

## Последовательность кнопки

1. Проверить аккаунт, назначение и выбранные коллекции. Заблокировать
   конкурирующий запуск и изменение параметров через UI.
2. Получить свежий состав «Мне нравится» и выбранных собственных/чужих
   плейлистов через существующий connection controller. Незавершённый или
   устаревший снимок не допускается к постановке заданий.
3. Построить канонический план с minimumCompletedAt начала операции.
   Зарегистрированные кандидаты проверяются по полному SHA-256 один раз на
   track ID. При missing/changed они инвалидируются, затем план захватывается
   заново. Denied/unreadable/stale останавливают обновление до enqueue.
4. Применить план атомарно с прежними fences. Если работы нет, завершить без
   открытия runner/helper. Иначе запустить runner только для этой папки и
   качества с текущим credential/session revision и выбранным лимитом.
5. Прежний pipeline скачивает аудио и обложку, записывает теги, проверяет
   результат и атомарно публикует Track/ref/asset/completed. Список библиотеки
   обновляется через поток SQLite, отдельное пересканирование не нужно.

Экран показывает стадии, байты при известном размере и число добавленных
треков. Файлы имеют устойчивые служебные имена; названия отображаются из тегов.
Существующие произвольные файлы без зарегистрированного external ID не
объявляются уже скачанными по одному названию. Удаление из удалённой коллекции
не удаляет музыку пользователя. Смена качества означает отдельный профиль.

## Отмена и закрытие

Уход со страницы не отменяет принятую операцию. Кнопка остановки отменяет
принадлежащие ей refresh/проверку/runner и ждёт завершения cleanup. Прогресс и
результат остаются у app-owned контроллера. Уже импортированные треки сохраняются.
Смена аккаунта/выбора либо отключение назначения также отменяет операцию.
Закрытие приложения запрещает новые операции, отменяет и дожидается контроллера
и runner до закрытия SQLite. Запуск приложения ничего не скачивает автоматически.

Диагностика содержит фиксированные числовые стадии/исходы/ошибки/счётчики.
Токены, пути, названия и тексты исключений туда не передаются.

## Проверки и оставшиеся границы

Контроллер проверен на свежести/гонках/повторах/ошибках хранения и чтения;
widget-проверки — на настройках, отмене, уходе со страницы, ширине 360/1200 и
масштабе текста 2. Реальные HTTP/SQLite/Windows helper на синтетических файлах
проверяют MP3 и FLAC с обложкой, повтор с полным хэшированием без второй загрузки,
отмену с явным повтором и отказ при недостаточном качестве.

Пользовательский credential и живая авторизованная загрузка не использовались.
Первую живую проверку выполнять на отдельном выбранном плейлисте из 1–3 треков.
Расписание, Android download, macOS qualification и новый дизайн идут далее.
