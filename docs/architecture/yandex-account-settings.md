# Подключение Яндекса — пакет 38

Пакет 37 подтверждён пользователем. В Windows настройках и отдельном Android
экране доступны подключение, выбор «Мне нравится»/собственных плейлистов,
проверка их состава и выход. Скачивание и изменение фонотеки на сервере
этот экран не выполняет. Повторное сканирование локальной музыки не требуется.

## Вход и хранение

Первый вариант принимает существующий OAuth-токен или документированный
callback `https://music.yandex.ru/#access_token=...`. Пароль не запрашивается.
Кнопка инструкции явно открывает [документацию автора клиента](https://ym.marshal.dev/token/)
во внешнем браузере. Другие адреса и дублированный access_token отклоняются.
Поле скрывает ввод, отключает подсказки/автокоррекцию и очищается при отправке.
Автоматическое получение/обновление токена пока не реализовано.

`flutter_secure_storage` 10.3.4 и `url_launcher` 6.3.2 закреплены в lockfile;
существующие зависимости не обновлялись. Windows backend 4.1.0 поставляется
с локальными исправлениями, см. [происхождение и патч](../../third_party/flutter_secure_storage_windows/UPSTREAM.md).
Неиспользуемый pre-4.x C++ механизм миграции удалён вместе с зависимостью ATL;
его MethodChannel явно возвращает NotImplemented. Продукт всегда выключает
backward compatibility и использует Dart DPAPI backend, миграция старых
секретов сторонних приложений не поддерживается.
Версия 11 библиотеки хранилища требует несовместимый с текущим file_picker
major win32; обновление всего стека ради входа не выполнялось.

Секрет находится только в одном именованном ключе системного хранилища.
SQLite содержит UID, имя, ревизию сессии и выбранные коллекции, без токена.
Диагностика/состояние UI получают только типы ошибок; сырые исключения,
HTTP-заголовки, callback URL и ответы с ошибками туда не передаются.
Из конфигурации стороннего загрузчика приложение ничего не импортирует.
Нет plaintext fallback, readAll/deleteAll или автоматического удаления
повреждённого хранилища. Полный ciphertext повреждённого Windows файла
сохраняется; безопасное удаление одного ключа может потребовать восстановления
системного хранилища, а не стирания всех чужих ключей.

- Windows: текущий пользователь DPAPI, запрет системных диалогов;
  зашифрованный временный файл с flush и атомарная замена MoveFileEx.
  Отказ замены сохраняет прежний ciphertext и удаляет только собственный temp.
- Android: отдельный storageNamespace, Android Keystore и стандартные
  RSA OAEP/AES GCM параметры выбранной версии, resetOnError=false.
  Backup приложения выключен, биометрия не запрашивается.
- macOS: несинхронизируемый legacy login Keychain для текущего unsigned
  desktop приложения; проверка на физическом Mac ещё нужна.

Это защита хранения средствами ОС, не защита от другого кода с доступом
к тому же пользовательскому сеансу. Обычный запуск не открывает хранилище
и не отправляет HTTP: контроллер создаётся при открытии настроек Яндекса.
Восстановление читает только локальную БД/хранилище. Сеть вызывают явные кнопки.

## Согласованность сессии

Кандидат сначала проверяет UID и каталог API. Только после этого репозиторий
резервирует SQLite writer, сверяет снимок действующих Yandex-сессий, активирует
новую ревизию и сохраняет привязанный к ней секрет. В транзакции находится
только короткий вызов OS storage, HTTP выполняется заранее. Ошибка записи
откатывает активацию и отзыв старых заданий. Если OS запись успела, а commit
не состоялся, восстановление отвергает несовпадающую привязку id/UID/revision
и требует нового входа. Двухфазная транзакция с ОС не предполагается.

Второй экземпляр приложения не может старым выходом стереть более новый вход:
DB fence сверяет всю активную сессию перед записью/удалением секрета. Ошибка
кандидата, включая 401, сохраняет прежний рабочий вход. 401 действующего
клиента отзывает текущую сессию и удаляет её ключ; ошибка удаления откатывает
DB изменение. Выход сохраняет локальную музыку, теги и зеркала коллекций.

Отмена до принятия credential commit ничего не сохраняет. После принятия
короткая запись дожидается результата, как и при закрытии приложения;
контроллер закрывает HTTP reader до SQLite и освобождает ссылку на токен.
Уход с экрана отменяет его операцию, сам сервис живёт до закрытия приложения.

## Коллекции и границы

При первом входе выбрано только «Мне нравится»; выбор плейлистов явный.
Повторный вход сохраняет прошлый выбор, включая снятый флажок «Мне нравится».
После перезапуска видны сохранённые коллекции; полный каталог по кнопке.
Исчезновение списка из каталога не стирает ранее выбранную коллекцию.
Проверка читает только выбранные списки через адаптер пакета 37 и прежние
tickets/CAS. Каждый успешно завершённый снимок сохраняется отдельно;
ошибка последующего списка не откатывает уже проверенные. Частичные/ошибочные
ответы оставляют прежний состав. Счётчик показывает позиции, включая повторы,
а не число новых файлов. Создания download jobs и скачивания здесь нет.

Android release получает INTERNET. Список плейлистов ограничен viewport
высотой 400 px и ListView.builder, каталог 2000 элементов не строится целиком.
Схема остаётся 13. Следующий пакет: download transport, владение и общий
бюджет raw/prepared workspace, затем соединение с планировщиком и кнопкой
обновления. Android SAF writer и macOS helper — отдельные шаги.

## Проверки

Новые тесты: 10 для реальных SQLite транзакций/двух соединений/откатов,
21 для parsing и настоящего Windows DPAPI в изолированном temp каталоге,
21 для контроллера и 7 widget checks. Данные синтетические, настоящий
аккаунт и ключи пользователя не читаются. Native DPAPI тесты проверяют
отсутствие plaintext, свежий backend, сохранность соседнего ключа,
повреждение ciphertext, отказ записи и блокировку атомарной замены.
На других ОС эта native группа пропускается. Widget проверки включают
320 px/двойной текст, 2000 плейлистов, сохранение выбора и уход с экрана.
Настоящий аккаунт, отзыв токена и Android Keystore после перезапуска
проверяются вручную по [чек-листу](../MANUAL_CHECKS.md).
