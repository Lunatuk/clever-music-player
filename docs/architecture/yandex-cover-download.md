# Обложка загружаемого трека

Пакет 45. Backend собран и проверен на синтетическом loopback API/CDN и настоящем
Windows helper; загрузка из аккаунта ещё не включена в пользовательском экране.

## Адрес и сеть

Метаданные выбранного трека дают optional `coverUri`. Поддержан известный шаблон
`avatars.yandex.net/get-music-content/<collection>/<object>/%%`, также с явным
`https://`. Размер всегда заменяется на **600x600**. Шаблон, хост и путь проверяются
до получения бинарных данных: запрещены другие домены/пути, userinfo, порты,
query/fragment, escapes, traversal, неизвестный размер и несколько placeholder.
Нет перехода к оригиналу или произвольному URL при ошибке. Другой CDN потребует
явного обновления адаптера после проверки контракта.

Основание — [get_cover_url в закреплённом SDK](https://github.com/MarshalX/yandex-music-api/blob/9ca132e5c18a72aab779c1fc68c169380a9357d0/yandex_music/track/track.py).
Отдельный loopback seam служит только тестам, не меняя production allowlist.

Прежний binary transport получил явный профиль `cover`: максимум **2 MiB**,
MIME JPEG/PNG/octet-stream либо отсутствие MIME. Для аудио прежний allowlist
сохранён: изображение не становится допустимым audio response. MIME является
первичным фильтром; фактический JPEG/PNG определяется по байтам независимо от
выбранного из двух image MIME. HTML/JSON/SVG/GIF/WebP и audio MIME отклоняются.
Затем обязательна проверка содержимого, одного HTTP заголовка недостаточно.

Новый HttpClient не получает OAuth, API client headers, cookies, redirect,
Range, retry или resume. Сохраняются ограничение объявленного/реального размера,
backpressure, total/idle deadline, flush, отмена и drain принятых операций.
Диагностика прежняя числовая: ни адрес, ни шаблон, ни ответ, ни название трека
в неё не добавляются. Исключения движка изображения заменяются фиксированным кодом.

## Байты, память и встраивание

Аудио и изображение скачиваются последовательно под одним DownloadLeaseOwner.
Во время изображения raw аудио остаётся зарезервированным. Изображение занимает
второй raw slot, учитываемый тем же [workspace](download-workspace.md), и хранится
в его обычном `audio.part`: raw stage означает opaque bytes, не доказательство
типа аудио. Общий лимит проверяется до image HTTP. После ограниченного чтения и
декодирования этот временный файл закрывается, а маленький immutable snapshot
остаётся в `YandexDownloadedTrack.cover`. RAM не является дисковой квотой:
закодированные байты ограничены 2 MiB, декодируемая картинка — 1024 по каждой
стороне и 1 048 576 пикселями, плюс ограниченные копии/накладные расходы движка.
Резерв учитывает потолок запроса, а не только реально полученный размер. Runner
должен выделять pool/workspace с запасом как минимум на audio ceiling + 2 MiB
и два raw slot, а для подготовки/публикации учитывать их перекрывающиеся копии.
Переданный `onProgress` пока сообщает аудио; image stage предстоит показать в UI.

DownloadedCoverDecoder допускает JPEG/PNG, проверяет PNG chunk boundaries/CRC,
IHDR/IEND/IDAT, завершение JPEG EOI, запрещает APNG и требует декодирования одного
кадра. [ImageDescriptor.encoded](https://api.flutter.dev/flutter/dart-ui/ImageDescriptor/encoded.html)
даёт размеры до [instantiateCodec](https://api.flutter.dev/flutter/dart-ui/ImageDescriptor/instantiateCodec.html)
и декодирования в исходном размере. Дескриптор, codec, image и buffer освобождаются
при любом исходе. Отмена проверяется между native await; уже принятая native
операция дожидается завершения. Это проверка читаемости движком, а не обещание
отклонения всех нарушений формата, которые JPEG decoder способен восстановить.

Потребитель передаёт `downloaded.expectation` и `downloaded.cover` координатору.
Expectation требует обложку, если она получена. Preparer резервирует отдельную
копию обложки и итоговое аудио; действуют все прежние проверки: полный audio
decode, размеры/длительность/теги, неизменность пакетов/PCM и точный digest
встроенной картинки. Сеть/картинка не являются доказательством готовности к
импорту. Проверены реальные PNG → MP3/FLAC и JPEG → M4A с импортом Track/ref/asset.

## Ошибки и владение

Если `coverUri` отсутствует, `cover == null`, image HTTP нет; preparer сохраняет
обложку исходного аудио, если она есть. Обложка не выдумывается из другого альбома.
Если адрес есть, ошибка загрузки/декодирования завершает всю попытку: нет тихого
пропуска картинки или публикации трека без обещанной обложки. Raw закрывается,
неудачное удаление удерживает квоту по прежнему контракту. Ошибки декодирования
помечают job как invalidMedia; HTTP сохраняет прежние typed failures.

Отмена пользователя, закрытие downloader, смена аккаунта/сессии, отключение
папки и timeout действуют и на изображение. Финальный writer fence выполняется
после картинки, перед handoff последнего job snapshot. Успешный raw закрывает
потребитель после всех читателей; close downloader его не удаляет. Immutable
cover живёт, пока на него есть ссылки, после чего освобождается GC.

## Далее

Нужны runner, связывающий credential с текущим account ID/revision/UID, ручная
кнопка с прогрессом/отменой и малая живая проверка API на выбранной коллекции.
Автозапуска сетевой загрузки или очистки workspace здесь нет. Приватный Android
lock, SAF publication/теги, настоящий телефон и macOS helper требуют отдельной
квалификации. Flutter decoder кроссплатформенный; весь Android pipeline пока
не объявляется готовым к загрузке. Расписание, дизайн и рекомендации — далее
по согласованному роадмапу.
