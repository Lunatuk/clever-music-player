# Android: запись подготовленного аудио через SAF (пакет 55)

Пакет55 добавляет физическую запись MP3/M4A/FLAC и связывает её с
[receipt и общим импортом54](android-publication-import.md). Публичное
скачивание песен пока выключено: Android backend тегов/обложек/проверки
декодирования и подключение общего runner остаются следующими задачами.
Windows51 остаётся актуальной; схема13 и зависимости не меняются.

## Создание и журнал

SAF не предоставляет общей транзакции с SQLite. Publisher использует
`createDocument`, а не переименование с предполагаемой защитой от замены.
По контракту provider возвращает новый document ID; имя может быть изменено
поставщиком ([DocumentsProvider.createDocument](https://developer.android.com/reference/android/provider/DocumentsProvider#createDocument(java.lang.String,%20java.lang.String,%20java.lang.String))).
Адаптер требует точного сгенерированного имени, нового ID относительно снимка
детей до создания, прежнего authority/tree и прямого членства; при создании передаётся MIME
выбранного формата.
Непрозрачный ID не преобразуется в файловый путь.

Приватный `audio-publications-v1` имеет owner marker, глобальный OS lock и
ограниченные AtomicFile-записи. Порядок операции:

1. INTENT сохраняется до любого обращения к provider. Допуск выполняется под
   текущим SQLite/lease fence; только приватный IO находится внутри этого gate.
2. CREATING сохраняется перед вызовом создания документа.
3. DOCUMENT и индекс authority/document ID сохраняются до открытия output.
   Output разрешён только один раз для нового URI в живом вызове create.
4. Источник и output закрываются. Полное повторное чтение сверяет число байтов
   и SHA-256, grants, членство, имя, размер и mtime до/после чтения.
5. READY сохраняется после проверки. Поздняя отмена не стирает этот результат.
6. Dart под действующим fence сохраняет долговечный receipt54. Затем допускается
   удаление native-журнала; музыка не удаляется. Общий importer54 заново
   проверяет документ перед атомарным Track/ref/asset/job commit.

Во время copy/readback SQLite writer и gate owner свободны для heartbeat.
Источник — только канонический обычный файл под `filesDir`, открытый read-only
без следования конечной ссылке, с проверкой размера через fstat. Seal удерживается
до завершения записи receipt и освобождения ресурсов. Минимальная версия
Android остаётся24; флаг O_CLOEXEC используется с публичного SDK27, без
вызова fcntlInt, доступного лишь с30
([Os API](https://developer.android.com/reference/android/system/Os#fcntlInt(java.io.FileDescriptor,%20int,%20int))).
На24–26 временный raw descriptor закрывается сразу после проверки/dup;
этот backend не запускает подпроцессы. Потоки используют буфер
64КиБ; 16 последовательных нулевых чтений завершаются ошибкой.

Допуск ограничен 64 операциями, 16ГиБ ожидаемых незавершённых байтов и 8ГиБ
на файл. Это логическая квота, не резервирование места у provider. READY
не занимает квоту незавершённых байтов, но занимает слот журнала до ack.
Обход непосредственных детей ограничен 10000 записями и 8МиБ символов ID/имён.

## Прерывание и повтор

После CREATING повтор не создаёт второй документ и не открывает старый output.
Reconciliation читает сохранённый URI; при разрыве между create и записью URI
может принять единственное совпадение точного имени только после полного
сравнения размера/хэша. Такое принятие не даёт права удаления документа.
Частичный, изменённый, отсутствующий либо неоднозначный результат сохраняется
для отдельного разрешения ситуации. Автоматического дописывания/удаления
частичной музыки в55 нет; эта политика нужна перед публичным запуском runner.

INTENT можно перепривязать к новому owner только до фазы эффекта. После неё
нужен read-only recovery с текущим owner. В живом вызове журнал без эффекта
убирается только при достоверном отсутствии вызова create. Авария процесса
в окне create сохраняет неоднозначность. Ошибки/неизвестные записи не выдаются
за успешную публикацию.

Native-журнал и Dart receipt читаются вместе; потеря native ack не запускает
новую запись. Receipt без native-журнала требует свежей проверки документа.
Закрытие publisher отменяет provider IO и ждёт завершения/receipt finalization;
после него caller закрывает журнал и БД. Отмена не обещает жёсткого срока
завершения для зависшего стороннего provider.

## Видимость в библиотеке

Сканер и одиночный импорт скрывают незавершённые управляемые документы.
До сохранения URI действует точное сгенерированное имя. После DOCUMENT
приватный SHA-256 индекс authority/opaque ID сохраняет защиту при переименовании.
Индекс записывается до output; читатель не выполняет AtomicFile recovery и
не меняет журнал. Повреждённый/недописанный marker скрывает соответствующий
документ. READY разрешает обычную музыку; записи диагностической проверки
скрыты даже в READY. При ack READY удаляется последним, чтобы прерывание
очистки не скрывало уже проверенную музыку. Для незавершённой проверки
INTENT сохраняется до удаления остальных markers.

Нулевой размер исключается из обхода и одиночного чтения. Неизвестный размер
сохраняет прежнюю поддержку provider. Эта защита относится к тому же authority
и ID: отдельные aliases другого provider не считаются тем же документом.
SAF grants и членство сверяются через
[DocumentsContract](https://developer.android.com/reference/android/provider/DocumentsContract).

## Проверка на телефоне и границы

Кнопка «Проверить запись в папку» теперь использует новый publisher55.
Он записывает nonce-marked тест4096байт с MIME audio/mpeg и расширением mp3,
проходит те же фазы/close/readback, затем удаляет только свой известный новый
URI с совпадающим полным либо частичным nonce payload. Это проверка байтового
хранилища, не MP3-кодека или воспроизведения: fixture не является песней.
Неизвестный/adopted URI не удаляется по одному имени. Повтор может убрать
известные собственные probe-остатки; неоднозначность сохраняется для отчёта.
Приватный временный источник удаляется в finally; автоматическое удаление
неизвестных файлов после аварии не добавлено. Legacy probe53 сохранён отдельно.

JVM fault tests проверяют ядро и видимость, Flutter tests — протокол,
SQLite/fence/receipt/recovery/drain и связь с общим importer. Настоящие
ContentResolver/AtomicFile не подменяются утверждением о проверке устройства.
APK55 требует двух запусков кнопки на Redmi и одного обычного Play.
Физические сбои provider, потеря grant, заполнение памяти и принудительное
завершение ещё требуют квалификации перед реальными скачиваниями.
