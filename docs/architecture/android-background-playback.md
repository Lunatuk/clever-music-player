# Android: фоновое воспроизведение, пакет 19

`AndroidMediaControlsService` создаёт один `AppAudioHandler` из audio_service
0.18.19. Он передаёт команды существующим PlayerService/PlaybackQueueService:
декодеры, предзагрузка, crossfade, история «Волны», база и статистика общие
с экраном. AudioSession 0.2.3 задаёт одну политику прерываний. Версии закреплены;
формат БД 9 и Android application ID Preview не меняются.

MainActivity наследует AudioServiceActivity: Activity и служба используют один
кэшированный Flutter engine. Возвращение к экрану не создаёт второй плеер.
SAF-канал вынесен в engine-owned ActivityAware AudioDocumentsPlugin: принятые
чтения продолжаются без Activity; только picker привязан к Activity.

## Системное управление

Manifest объявляет mediaPlayback foreground service, MediaButtonReceiver,
WAKE_LOCK, FOREGROUND_SERVICE и FOREGROUND_SERVICE_MEDIA_PLAYBACK.
Разрешения всего хранилища/микрофона/телефонии не добавляются. Медиасессии
освобождены от runtime POST_NOTIFICATIONS; это не обычные уведомления загрузки.
Белая notification-иконка сохраняется resource shrinker через keep.xml.
Lint не распознаёт MediaSession-исключение в нативной зависимости. `lint.xml`
исключает только NotificationPermission с точным отправителем
com.ryanheise.audioservice.AudioService; проверки других уведомлений остаются.

Проекция состояния передаёт название, исполнителя, альбом, длительность и
локальную миниатюру; ID — числовой ID трека или SHA-256 исходной ссылки.
Служебный ID не содержит исходный URI. Сообщение системной ошибки фиксировано.
Обычный ход позиции прогнозируется системой; при seek/расхождении >=750 мс
адаптер публикует обновление, не отправляя каждый тик декодера в Android.

Play/Pause/Seek/Next/Previous, включая аппаратные клики, используют общие
команды. При завершении с продолжением очереди публикуется buffering/playing;
при восстановлении после недоступного файла учитывается также промежуток
между автоматическими попытками. Служба не выходит из foreground посреди
такого перехода. Исчерпание восстановления публикует конечную ошибку.

Stop дожидается остановки обоих декодеров, освобождает audio focus и только
затем публикует idle. Он завершает выбранный трек; новый запуск — выбор в
списке. Кнопка Stop есть на экране и в развёрнутом системном управлении
(конкретное отображение кнопок зависит от Android/HyperOS).

## Прерывания и питание

На Android автоматическая обработка прерываний just_audio выключена на обоих
декодерах. Общая AudioSession настроена как music, pause-when-ducked.
Потеря фокуса/отключение наушников ставит на паузу логический плеер, включая
оба декодера crossfade, без изменения пользовательской громкости. Окончание
прерывания само не включает звук; продолжение — явный Play.

При обычной паузе androidStopForegroundOnPause=true: foreground/wake lock
освобождаются, медиасессия остаётся для продолжения. При игре удаление задачи
из недавних не вызывает Stop в обработчике. Android/OEM всё же может завершить
процесс; перезагрузка/принудительная остановка не вызывают автозапуск музыки.
История очереди остаётся сеансовой. Автовосстановление после process death
и автоматическая смена системных настроек энергосбережения не добавлены.

Android 15+ ограничивает запрос фокуса приложением в фоне: необходим foreground
service или верхняя Activity. Переход playing/loading публикуется до запуска
декодера; порядок нативных каналов, возобновление из уведомления и ограничения
HyperOS проверяются на телефоне. Симуляция декодеров не доказывает работу ОС.

## Закрытие и проверки

Адаптер закрывает приём команд, отменяет подписки, дренирует принятые команды,
закрывает subjects и деактивирует сессию. Владение декодерами/SQLite остаётся
у AppDependencies. Инициализация/закрытие идемпотентны; поздняя регистрация
не возобновляет публикацию закрытого handler. Очистка пытается выполнить
каждый шаг и сохраняет первую ошибку.

Автотесты проверяют проекцию, обновление метаданных одного ID, ограничение
публикаций позиции, команды/историю, естественное завершение и восстановление,
оба декодера при прерывании, Stop/закрытие, уход Android root в фон и возврат.
Нативные Kotlin/manifest/resources проверяются release-сборкой и lint; APK —
подписью/CRC/ZIP и ELF 16 КиБ alignment. Физического Android-устройства в
сборочной сессии нет; [точечные проверки](../MANUAL_CHECKS.md) выполняет пользователь.
