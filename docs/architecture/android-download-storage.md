# Android: подготовка хранилища загрузок

Пакет 49 начинает перенос ручного обновления библиотеки на Android. Полный
загрузчик на телефоне пока не включён: сначала проверяем реальные private IO
и выдачу SAF-доступа, затем подключаем публикацию, теги/обложки и общий runner.
Различия названий/альбомов в данных провайдера оставлены как есть по просьбе
пользователя; нечёткое объединение треков не добавляется.

## Временные данные

`getApplicationSupportDirectory()/android-downloads` — внутренняя область
приложения. Это обычные пути, не `content://` и не cache. Существующий native
asset `cmp_file_ops` использует POSIX `flock`, `O_NOFOLLOW`, `link/unlink`;
Dart-проверка платформы теперь разрешает Android. Ограничение 16 KiB ELF
сохраняется. SAF-папки этим адаптером не обслуживаются.

Кнопка проверки создаёт отдельный свежий `probe-*`, открывает существующий
DownloadWorkspace, проверяет исключение второго владельца, лимит reservation,
запись/чтение 4096 байт, освобождение reservation, отказ от замены существующего
файла и успешный перенос в свободное имя. В `finally` сначала закрываются lease
и workspace; затем удаляется только собственный свежий дочерний каталог после
проверки канонических границ. Если cleanup reservation завершается ошибкой,
закрытие workspace всё равно освобождает OS lock; повреждённые данные остаются
для разбора, не объявляются очищенными. При отмене принятый короткий IO завершается до
очистки. Существующие production workspaces и неизвестные соседние файлы
проверка не открывает. После аварийного завершения probe может остаться;
автоматического удаления неизвестных каталогов по возрасту нет.

Это проверка возможностей файловой системы и поставленного native asset,
а не измерение скорости, длительная загрузка или резервирование физического
места. Reservation ограничивает логический бюджет, не свободное место ОС.
Настоящий ENOSPC при многочасовой загрузке и восстановление Android-публикации
после принудительного завершения должны быть проверены следующим пакетом.

## Папка назначения

Отдельный `pickDownloadFolder` запрашивает READ + WRITE + PERSISTABLE для
`ACTION_OPEN_DOCUMENT_TREE`. Сохраняются только фактически возвращённые флаги;
для назначения необходимы оба разрешения. Обычный импорт музыки остаётся
с запросом READ. Новый выбор не вызывает сканирование и не меняет корни
библиотеки. Выбор хранится в отдельном setting `android.download_destination.v1`.

`inspectDownloadFolder` проверяет сохранённый grant, что корень является
каталогом, и `FLAG_DIR_SUPPORTS_CREATE`. Имя ограничено 256 символами. Без прав,
при недоступном provider или отсутствии создания файлов новая папка не заменяет
сохранённую. Повторная проверка сбрасывает устаревшее readiness до IO; исчезнувший
доступ не объявляется готовым. Отмена picker сохраняет прежний выбор.

В выбранной папке пакет 49 не создаёт и не удаляет даже тестовые файлы.
Флаг provider — предварительное подтверждение возможностей, а не гарантия
будущей успешной записи. Фактическое создание, закрытие, проверка байтов,
конфликты имён и восстановление принадлежат будущему SAF publisher.
«Сбросить выбор» удаляет только настройку: grant не отзывается, потому что
его может использовать импорт существующей музыки.

Контроллер принадлежит приложению. Повторные действия исключены, при закрытии
отменяется private check, ожидаются уже принятые записи настроек/IO, и только
затем закрывается SQLite. Поздний picker не сохраняет новую настройку.
Произвольный текст platform/OS exceptions в UI не попадает.

## Следующие шаги

1. SAF publisher с журналом во внутреннем хранилище, ограниченной потоковой
   записью, закрытием/повторным чтением, полным SHA-256 и восстановлением.
   Не переносить desktop `rename`/блокировки буквально на document provider.
2. Android backend подготовки MP3/M4A/FLAC: теги, обложка, проверка аудио;
   квалификация библиотек, лицензий, отмены и лимитов.
3. Подключить существующие аккаунт/коллекции/очередь/планировщик и кнопку
   ручного обновления; только после этого включить `supported` на Android.
4. Проверить реальную загрузку, повтор, отмену, потерю grant, заполнение памяти,
   перезапуск/принудительное завершение и работу параллельно с воспроизведением
   на Redmi Note 14 Pro / Android 16. После этого — расписание и дизайн.
