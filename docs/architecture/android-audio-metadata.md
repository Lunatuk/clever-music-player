# Android: общие правила метаданных, пакет 23

До пакета 23 AndroidImportController сохранял title ?? displayName, включая
расширение файла, а пустой artist не заполнял из имени. На видео проверки 22
это видно у файлов вида «BOOKER - Название.mp3»: на desktop уже работал
FilenameMetadataParser, на Android оставался неизвестный исполнитель.

mergeAudioDocumentMetadata передаёт displayName и встроенные поля Android в
существующие FilenameMetadataParser/mergeMetadata. Импорт файла и обход папки
используют один этот путь. Аудио/теги на диске не переписываются, дополнительного
чтения файла и запроса сети нет. Нативный канал и схема SQLite 9 не меняются.

Правила:

- Полезные встроенные title/artist/album/albumArtist/genre имеют приоритет;
  имя заполняет только пропущенные поля. Пустые и типовые placeholder-теги
  фильтруются общими desktop-правилами. Текст нормализуется тем же кодом.
- Имя «Исполнитель — Название.mp3» даёт отдельного исполнителя и название
  без расширения. Для простого имени вроде scars.mp3 исполнителя не выводят.
  Это эвристика имени, а не подтверждённая музыкальная идентичность.
- Используется только SAF displayName, никогда URI, tree/document ID или
  имя родительской папки. При отсутствии имени и полезных тегов — «Без названия».
  Непустой generic title при отсутствии имени сохраняется как запасная подпись
  с низкой уверенностью, чтобы не терять единственный известный заголовок.
- Track.metadataSource/metadataConfidence отражают общие правила качества:
  embeddedTags при полезных title/artist/album, filename при распознанном имени,
  fallback при простом/неизвестном заголовке. Происхождение отдельных полей
  и несколько жанров остаются следующей частью модели медиатеки.
- Повторный импорт того же URI обновляет прежнюю автоматическую запись.
  TrackImportRepository сохраняет ID, владельца, addedAt, ручные метаданные
  (в том числе явно очищенные поля), custom cover и пользовательские связи.
  Папки продолжают скрываться/возвращаться по правилам пакета 22.

Существующие записи улучшаются при явном «Обновить» папки или повторном выборе
того же URI. Массовая миграция тегов/полное сканирование при запуске не нужны.
Разные URI одного файла пока остаются разными источниками: выбор файла через
«+» и импорт через дерево могут дать разные URI. Этот пакет не вводит алиасы
и не объединяет по совпадению заголовка/исполнителя.

Добавлены 15 тестов: приоритет и дополнение тегов, русские имена/тире/скобки,
placeholder/нормализация, простые/неоднозначные имена, отсутствие имени,
сопоставление с desktop reader с внедрёнными тегами и четыре SQLite-сценария обновления,
файлов/папок, ручных очищенных полей/обложки/истории/плейлиста и непрозрачного URI.
Старые тесты отмены, владения папками, фонового управления и проигрывателя
включены в полный регрессионный прогон. Проверка на физическом телефоне —
две небольшие проверки имени без тегов и приоритета встроенных тегов.
Пользователь подтвердил работу пакета 23 и приложил видео 15 октября 2026 года.
