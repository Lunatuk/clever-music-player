# Android: сохранённые папки и обновление, пакет 21

AndroidFolderBookmarks хранит небольшой список папок для повторного импорта.
Это закладки обновления, отдельно от владения треками и файловых LibraryFolders.
Схема SQLite 9, внутренние ID, оценки/история и URI треков не меняются.

## Хранение и переход с пакета 20

Список лежит в AppSettings под ключом android.audio_folder_bookmarks.v1:
version, точный tree URI, имя и UTC-время последнего полного обновления без
ошибок файлов. Максимум 128 папок/256 КиБ JSON, имя до 256 символов.
Повторный URI обновляет запись; сходство названия не означает тождество.
Неизменившиеся данные повторно не пишутся.

При первом запуске без этого ключа listAudioFolderGrants читает постоянные
read grants Android. Принимаются только чистые tree URI, а не отдельные
документы внутри дерева. Так папки из версии 20 попадают в список без picker
и нового сканирования. После bootstrap даже пустой список записывается:
убранные из него папки не возникают снова из оставшихся grants.

Повреждённый JSON/неизвестная версия/повторные или слишком большие записи
не заменяются пустым списком. Экран показывает ошибку списка; имеющиеся треки
и импорт отдельных файлов остаются доступны. Настройки и другие ключи
плеера не меняются.

Мутации сериализованы, публикация выполняется после успешной DB-записи.
Ошибка одной записи не блокирует последующие операции. Close запрещает новые
операции и дренирует принятые загрузки/записи/проверки; поздние результаты
не уведомляют закрытый виджет. Корень Android закрывает importer, затем
закладки и только после них AppDependencies/SQLite.

## Обновление и доступ

Кнопка «Обновить библиотеку» проходит сохранённые папки без системного выбора.
На экране «Папки» можно обновить одну папку, добавить новую, проверить доступ
и выбрать прежнюю папку заново для восстановления разрешения.
inspectAudioFolder проверяет постоянный read grant и читает имя/MIME корня
через ContentResolver на worker. Отсутствие grant или ошибка провайдера
отображаются как недоступность, не удаляют треки и не требуют сети от плеера.
Проверка может обратиться к выбранному пользователем облачному провайдеру.

Восстановление требует ту же точную ссылку: другая выбранная папка не подменяет
старую запись/URI треков. Если каталог переместился и его URI изменился,
нужно добавить его отдельно; надёжное сопоставление требует будущих алиасов/
идентичности документов. Отказ/cancel picker не меняет список.

Снимок папок для обновления ждёт уже принятые изменения списка. Позднее чтение имени обновляет только существующую закладку; убранная папка не регистрируется заново при повторном обходе. Удаление проверяет busy также при вызове callback, чтобы старый обработчик между кадрами не обходил блокировку.

Обновление использует прежний постраничный импорт. Ошибка одной папки не
прерывает остальные; отмена прекращает переход к следующей. Сессия и Future
закрытия сбрасываются после каждой папки. Последняя успешная дата меняется
только после полного обхода, освобождения сессии и отсутствия ошибок файлов.
При отмене/частичном результате остаётся прежняя дата.

## «Убрать из списка» и границы

Действие убирает только закладку обновления. Треки, пользовательские данные,
файлы и grants остаются. Это написано прямо на экране. Автоматически отзывать
доступ пока нельзя: тот же tree grant может обслуживать URI, добавленные
прежним импортом без учёта источников. Повторное добавление той же папки
использует прежние ID через существующий TrackImportRepository.

Полный реестр источников с принадлежностью треков, отключением/удалением,
учётом неиспользованных grants, алиасами разных URI и Android-хэшами ещё
впереди. Разные URI одного физического файла пока остаются разными строками.
Перестройка источников не подменяется сравнением названий.
Расписание, Яндекс, жанровая модель, восстановление после process death
и длительная dataSync-служба этим пакетом не вводятся.

## Проверки

22 новых сервисных/SQLite/канальных сценария, 6 widget-сценариев:
bootstrap 20, restart/forget, сериализация/ошибка записи, JSON/лимиты,
no-op записи, доступ/late results/close, повтор без picker, сохранение ID/
ручного имени/лайка, отказ одной папки, отмена между папками, безопасное
восстановление и доступность обычного импорта при ошибке закладок.
UI проверен при 200% тексте в 390×844 и 844×390. Фоновый root-тест использует
явно внедрённые закладки; он не вызывает настоящий native channel в Windows.
Прежние 6 JVM-тестов обхода остаются в проверках Android.

Нативный provider/реальные grants физического телефона по-прежнему проверяет
пользователь. [ContentResolver.getPersistedUriPermissions](https://developer.android.com/reference/android/content/ContentResolver#getPersistedUriPermissions()),
[SAF и сохраняемые разрешения](https://developer.android.com/training/data-storage/shared/documents-files#persist-permissions).
