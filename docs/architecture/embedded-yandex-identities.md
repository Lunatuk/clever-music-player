# Ссылки Яндекс Музыки в локальных тегах

Пакет 64, 13 ноября 2026 года. Первый шаг выполняется в Windows-сканировании.
Схема SQLite — 13. Чтение комментариев Android и проверка наличия перед
загрузкой следуют отдельными шагами.

## Чтение источника

AudioMetadataReaderService извлекает комментарии при обычном чтении тегов.
Поддержаны M4A ©cmt, MP3 COMM и TXXX comment, FLAC/OGG COMMENT и DESCRIPTION.
Общий ридер также передаёт комментарии RIFF/APE/AIFF при наличии.
В vendored audio_metadata_reader добавлены передача комментариев в общую модель
и разбор COMM с Latin-1, UTF-8, UTF-16 с BOM и UTF-16BE.
Формат COMM описан в [ID3v2.4, разделе 4.10](https://id3.org/id3v2.4.0-frames).

embeddedYandexIdentity принимает полную исходную ссылку из комментария.
Поддержаны HTTP/HTTPS, хосты music.yandex.ru/com/by/kz/uz и пути
`/album/<id>/track/<id>` либо `/track/<id>`. Альбом сохраняется в variantKey.
Регистр хоста, окружающие пробелы, крайние NUL-разделители ID3, tracking query
и завершающий слеш обрабатываются при чтении. Числовые ID сохраняют ведущие нули.
Пределы — 32 комментария, 4096 символов в одном и 32 цифры в ID.
Разные валидные идентичности в комментариях дают неопределённый результат.
Ошибочный URL, сторонний хост, credentials/port и некорректный UTF-8 пути
обрабатываются как отсутствие распознанной ссылки.

Ссылка обозначает заявленный источник файла. Подтверждённая загрузка, доступность
и качество файла учитываются существующими самостоятельными механизмами.

## Сохранение

TrackImportRepository.upsertScannedTracks принимает optional
embeddedYandexIdentities с точным путём импортируемого файла и nullable ID.
Входные коллекции копируются до первого await. Треки и связи сохраняются одной
SQLite-транзакцией. Отказ вставки ссылки откатывает весь пакет, после чего
сканер может изолировать проблемный файл прежним построчным повтором.

Чтение, хэширование и проверка стабильности файлов выполняются до транзакции.
В буфере сохраняется полный файловый fingerprint, повторно проверяемый перед
записью. Новая связь получает origin embeddedTag. Повтор того же ID сохраняет
первый linkedAt. Успешно прочитанный новый комментарий обновляет прежние
embeddedTag-связи Яндекса для этого файла. Очистка такой связи выполняется через
ExternalTrackRepository.unlink вместе с зависимой записью проверенного ресурса.
Связи с происхождением providerResponse/manual сохраняют свой приоритет.
Пропущенный путь в карте означает отсутствие новых сведений об источнике.

## Старые файлы и повторный проход

AppBootstrap передаёт сканеру существующий SettingsRepository. Для каждой папки
хранится маркер `scan.yandex-source-ids.v1.<folderId>`.
При первом обновлении уже индексированной папки неизменившиеся файлы проходят
чтение тегов с getImage=false. Изображения при таком чтении пропускаются.
Обычные новые или изменённые файлы отдают комментарий вместе с метаданными.

Полностью завершённый проход без ошибок отмечает версию чтения источников.
Отмена, ошибка чтения/сохранения или изменение буферизованного файла оставляют
дополнение связей доступным следующему проходу. Fallback после ошибки метаданных
помечает источник для последующего чтения. Отсутствие поддерживаемых тегов
обрабатывается отдельно от отказа их чтения.

Дальнейший неизменённый обход использует прежний быстрый путь с хэшированием.
В итоге сканирования отображается «Связано с Яндексом» с числом разных доступных
файлов этой папки, имеющих хотя бы одну связь Яндекса. Счётчик сохраняет значение
на повторном проходе и включает ранее полученные связи загрузчика.

## Следующие отдельные шаги

1. Подключить чтение исходных ссылок в Android SAF-импорт.
2. Согласовать формат полного файлового SHA-256 у сканера и загрузчика.
3. Проверять доступные локальные файлы перед загрузкой с учётом выбранного
   профиля качества. Пользователь выбрал скачивание при переходе на другое
   выбранное качество.
4. Группировать файловые варианты одной композиции в медиатеке.
5. Добавить сравнение аудио и аудиоотпечатки для файлов с недостаточными ID.

## Проверки

Полный набор 2531 Flutter-тест прошёл, анализатор чистый. Добавлено 48 сценариев
для источников, кодировок COMM, настоящих MP3/M4A/FLAC, атомарного импорта,
отката, происхождения связей, старых файлов, отмены и повторного прохода.
Четыре прежних тестовых адаптера обновлены под optional аргумент импорта.

Отдельный локальный тест прочитал шесть исходных файлов пользователя и выполнил
их импорт в изолированную БД в памяти. Сверены ожидаемые ID трека и альбома.
Повторный проход сохранил шесть связей при нуле чтений метаданных.
