# Прогресс и остановка сканирования

Пакет 10 продолжает выделение логики библиотеки из экрана и обработку больших коллекций. Схема БД остаётся 9. Остановка — запрос на прекращение дальнейшей работы с сохранением уже завершённых операций, без отката всего сканирования.

## Контракт и состояние

`LibraryScanControl` передаёт запрос отмены и локальные снимки `LibraryScanProgress`: папка, этап, завершённые файлы, добавления/обновления/ошибки, имя файла и прочитанные байты. Процент всего обхода неизвестен без предварительного прохода; UI показывает число файлов и прогресс хэша текущего файла. Пути/имена остаются в UI, в диагностику не передаются.

`LibraryController` создаёт отдельный control для каждой команды добавления/сканирования. Фаза `cancelling` сохраняет резервирование библиотеки; повторная отмена/конкурирующая команда не начинает новую работу. Прогресс публикуется через отдельный `ValueListenable`, с объединением изменений в интервалах 100 мс и выдачей последнего снимка при завершении. Обычный Listenable состояния команды не получает тики прогресса. Идентичность control защищает от поздних сообщений завершённой операции. Закрытие из обычного или прогресс-слушателя безопасно; таймеры и уведомления закрытого контроллера прекращаются.

`ControlledLibraryFolderScanner` добавлен как отдельный контракт. Прежние callback-адаптеры принимаются для совместимости, но остановка у них возможна только на границах их Future. `AppDependencies` подключает настоящий контролируемый сканер и для добавления, и для одиночного/общего пересканирования. Management создаёт control папки с переносом отмены, добавляет накопленные счётчики и номер/общее число папок, прекращает обход следующих источников. Поздний прогресс прежней папки игнорируется.

## Границы остановки и сохранение данных

Сканер проверяет отмену до старта и между шагами чтения/метаданных/записи. Подписка на каталог останавливается через `StreamIterator.cancel()`, включая ожидание следующего события. Отмена не считается ошибкой чтения. Частичный файл не сохраняется как готовый и не очищает прежний подтверждённый хэш. Уже начавшийся upsert завершается и считается обработанным; завершённые изменения состояния seen/hash сохраняются до возврата результата.

Только полный обход без запроса остановки на момент решения о финализации разрешает отметить невстреченные записи отсутствующими и обновить `lastScannedAt`. Ошибка обхода также не обновляет дату полного сканирования. Полностью завершённые предыдущие папки общей операции остаются завершёнными; остановка не откатывает их. Если запрос пришёл во время уже начавшейся финальной записи, она завершается: реально просмотренные каталоги не становятся неполными задним числом. У добавленного источника после ранней остановки может остаться часть импортированных треков; повторный обход дополняет их по существующим ID/пути.

`LibraryScanResult.wasCancelled` и `processedFiles` отличают остановку и завершённые файлы от числа найденных файлов, включая прерванный текущий. Итоги нескольких папок суммируются. В UI остановка отображается отдельным результатом; реальные ошибки законченных шагов сохраняются. `scanCancelRequested`/`scanCancelled` фиксируются отдельно от отказов, без произвольного текста или путей.

## Чтение хэша и завершение приложения

Контролируемое хэширование использует рабочий isolate с каналами команд/прогресса/результата. Отмена передаётся сообщением, а не `Isolate.kill`: проверка выявила, что принудительное завершение во время асинхронного открытия/чтения может оставить занятый файл Windows. Рабочий код читает блоки 64 KiB, проверяет запрос между чтениями и всегда закрывает `RandomAccessFile` через finally. Только после закрытия IO/канала команд публикуется результат или отмена и завершается isolate; вызывающий код ожидает уведомление выхода и закрывает порты. Прежний вызов без control использует тот же ограниченный по памяти алгоритм.

Запрос не обрывает уже начатый вызов ОС, парсер метаданных/обложки или запись SQLite. Они завершаются до разблокировки библиотеки; на сетевом/неисправном накопителе это может занять время. `close()` запрашивает отмену и по-прежнему ожидает дренирование всего текущего доступа к БД; ожидающий сканер возвращает `closed`. Поздний picker не задерживает закрытие и не запускает обход. Гарантии относятся к штатному закрытию API, принудительная остановка процесса остаётся отдельным случаем.

Отмена в процессе парсинга, хранение курсора для продолжения после перезапуска, предварительный подсчёт коллекции, параллельные обходы и URI-источники Android в этом пакете не реализуются. Они требуют отдельных адаптеров и проверок. Панель `LibraryScanStatus` вынесена из `HomeScreen` для повторного использования и последующей переработки дизайна.

Дополнение пакета 13: штатный обход переиспользует один lazy hash-worker на папку, ReadInto читает блоками до 256 КиБ (малые файлы — меньше). Каждый запрос закрывает свой файл и канал отмены до ответа; worker завершается при close сессии до результата/диагностики сканирования. Старый одиночный путь сохраняет 64 КиБ. Правила отмены/побайтового совпадения остаются прежними. Подробный профиль и границы: [оптимизация импорта](import-performance.md).
