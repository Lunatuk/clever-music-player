# Android: первый прототип доступа к музыке

Пакет 17 проверяет ранний риск переноса: сможет ли общий плеер проигрывать
`content://` прямо от Android-провайдера и сохранять доступ после перезапуска.
Целевой телефон пользователя — Xiaomi Redmi Note 14 Pro, Android 16.

## Границы

- Android-проект создан шаблоном установленного Flutter 3.41.9: AGP 8.11.1,
  Gradle 8.14, Kotlin 2.2.20, compile/target SDK 36, min SDK 24, NDK 28.2.
- Application ID `dev.lunatuk.clever_music_player.preview`, имя **Clever Music Preview**.
  Это отдельная песочница; Windows-библиотека не переносится на телефон.
  Release APK прототипа подписан локальным debug-ключом, не ключом публикации.
  `allowBackup=false` отключает Auto Backup. Некоторые OEM отдельно переносят
  данные между устройствами; исключения `dataExtractionRules` ещё нужны перед
  выпуском. Перенос базы сам по себе не переносит grants к её URI.
- Android-ветка `main.dart` использует прежний bootstrap, SQLite schema 9,
  одну общую очередь и один логический плеер с двумя декодерами.
  Windows/macOS сохраняют свой экран. Новый компактный экран — технический
  прототип, не окончательный редизайн приложения.
- На этом этапе выбираются **отдельные файлы**, до 64 за один выбор.
  Папки/MediaStore, массовая медиатека, удаление источников, URI-хэширование,
  управление grants и полная мобильная навигация ещё не перенесены.
  Повтор той же строки URI обновляет прежнюю запись. Разные URI одного файла
  ещё не распознаются как точные копии.

## Нативный адаптер

Обновление пакета 20: выбор папки и постраничный обход вложенных каталогов
добавлены отдельной возможностью [импорта папки](android-folder-import.md).
Описание выбора отдельных файлов ниже остаётся действующим; общий реестр
источников, MediaStore и URI-хэширование ещё не перенесены.

В пакете 19 `MainActivity` наследует `AudioServiceActivity` и один раз подключает
`AudioDocumentsPlugin` к общему Flutter engine. Плагин предоставляет канал
`audio_documents` с двумя методами:

1. `pickAudio`: `ACTION_OPEN_DOCUMENT`, `CATEGORY_OPENABLE`, `audio/*`,
   множественный выбор. Для каждого принятого URI вызывается
   `takePersistableUriPermission` **только с read flag**. Непостоянный доступ
   не создаёт запись, отказ/превышение лимита возвращается числовым счётчиком.
   Отмена возвращает null. Повторный открытый picker отклоняется.
2. `readAudio`: проверяет постоянный grant, открывает/закрывает descriptor,
   читает display name/size и теги через ContentResolver/MediaMetadataRetriever
   в одном рабочем потоке. Аудио не копируется в приложение и не загружается
   целиком в память. Отсутствие тегов не блокирует читаемый трек.
   Встроенная картинка до 8 МиБ преобразуется в WebP до 384 px / 256 КиБ;
   канал передаёт только миниатюру. MediaMetadataRetriever сам выделяет исходные
   байты картинки до нашей проверки размера — это не жёсткий предел памяти
   внутри системного API. Descriptor/retriever/bitmap освобождаются.

Общие разрешения на хранилище и `MANAGE_EXTERNAL_STORAGE` не запрашиваются.
SAF не требует разрешения на весь каталог; grants выдаются выбранным документам.
При перемещении/удалении файла или отзыве доступа сохранённый URI может перестать
работать: экран предлагает повторный выбор, остальные записи продолжают работать.
См. [официальный контракт SAF](https://developer.android.com/training/data-storage/shared/documents-files).

## Импорт и жизненный цикл

`AndroidAudioDocuments` валидирует ответ канала, сохраняет исходную строку URI,
ограничивает число элементов/размер картинки. `AndroidImportController` резервирует
операцию до picker, последовательно читает документы и сохраняет их через прежний
`TrackImportRepository`. Транзакция остаётся короткой, IO выполняется до неё;
ручные теги/обложки/ID/оценки прежней записи сохраняются.
Ошибка одного документа или кэша картинки не прерывает остальные.

Владелец экрана закрывает приём импорта, дожидается принятого чтения/записи и
только потом освобождает общие зависимости/SQLite. Ожидание открытого picker
не блокирует close: его поздний результат уже не начинает IO/запись/уведомления.
Неиспользованные grants после отказа БД пока остаются у приложения; их учёт и
освобождение нужны перед массовым импортом. При уничтожении процесса посреди
picker результат может быть потерян; пользователь повторяет выбор.
Как и desktop widget dispose, завершение процесса ОС не гарантирует drain.

## Воспроизведение и следующие шаги

Минимальный экран: список с обложками, выбор одним нажатием, Play/Pause,
Previous/Next, перемотка. Прежние URI/preload/crossfade используют общий плеер.
В пакетах 17–18 при сворачивании запрашивалась пауза. Пакет 19 заменяет эту
границу [фоновой медиаслужбой](android-background-playback.md): уведомление,
экран блокировки и гарнитура управляют прежним плеером. Метаданные читает
плагин, принадлежащий engine: принятые чтения завершаются и при отсутствии
Activity. Picker требует Activity; при окончательном отсоединении его ожидание
отменяется, при смене конфигурации сохраняется. Рабочий поток закрывается
при уничтожении engine, а не при уходе экрана в фон.

Автотесты с каналом/искусственным декодером проверяют контракт и гонки, но не
реальные grants, аппаратный декодер или поведение HyperOS. APK дополнительно
проверяется по CRC, подписи, ZIP/ELF 16 КиБ alignment. Статическая проверка
не заменяет запуск на 16 КиБ устройстве:
[проверки Android](https://developer.android.com/guide/practices/page-sizes).

## Воспроизведение сборки

Нужны Flutter 3.41.9, JDK 17+, Android SDK 36 / build-tools 35+ / NDK 28.2.
На Windows использовать ASCII-путь вне OneDrive для сборочной копии.
SDK задаётся через `ANDROID_HOME`, JDK через `JAVA_HOME`; `local.properties`,
ключи и сборочные файлы не входят в Git.

```powershell
flutter pub get --enforce-lockfile
flutter build apk --release --no-pub --target-platform android-arm64 --split-per-abi --build-number=17
python tool/verify_android_apk.py build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
```

На этой Windows-машине SDK установлен в
`%LOCALAPPDATA%\CleverMusicPlayerAndroid\sdk`; JDK — `C:\Program Files\Java\jdk-17.0.2`.
Flutter генерирует `local.properties` с Windows-разделителями, на которых lint
сообщает `PropertyEscape`. Для локального lint после APK-сборки значения SDK/Flutter
в этом игнорируемом файле приведены к `C\:/...` и запущено
`gradlew -Ptarget-platform=android-arm64 :app:lintRelease --rerun-tasks -x compileFlutterBuildRelease`.
Это не отключение lint: ранее собранный Dart-код повторно не компилируется,
а все нативные lint tasks выполняются заново. На Linux CI такого пути нет.

`android-checks.yml` добавляет APK/alignment/native lint к существующим desktop
format/analyze/test/build проверкам. Запуск GitHub Actions из локальной сессии
не выполняется; фиксируются только реально выполненные локальные проверки.
