# Android: импорт выбранной папки, пакет 20

Пакет 20 подтверждён пользователем на телефоне. С пакета 21
[сохранённые папки](android-saved-folders.md) обновляются без повторного picker;
описание границ ниже относится к исходному пакету 20.

Системный ACTION_OPEN_DOCUMENT_TREE выдаёт read-only постоянный доступ к
выбранной папке. Пользователь выбирает папку обычной кнопкой «Добавить папку»;
Android сам ограничивает доступные каталоги. Общее разрешение на хранилище,
MediaStore и запись/изменение исходных аудиофайлов не добавлены.

AudioDocumentFolders — отдельная возможность адаптера AndroidAudioDocuments;
прежние клиенты отдельных документов не обязаны реализовать её. Канал открывает
сессию обхода, возвращает страницы и закрывает сессию. URI сохраняются буквально.

## Нативный обход

DocumentTreeWalker — независимый от Android API последовательный обход.
Он открывает один cursor каталога, сохраняет продолжение между страницами,
возвращает до 64 аудиоссылок и выполняет до 256 шагов за запрос. Pending-каталоги
и множества уже посещённых ID защищают от циклов/повторных ссылок провайдера.
Общий предел — 100 000 объектов/открытий каталогов; превышение означает ошибку
с сохранением ранее импортированного, а не успешный обрезанный результат.
Метаданные/картинки/аудиобайты всей коллекции не собираются в память.

AudioDocumentsPlugin открывает дочерние URI через DocumentsContract. Cursor
читает только ID/MIME/display name; audio/* или прежние расширения
mp3/flac/m4a/aac/ogg/wav поступают в импорт. Изображения и остальные документы
не импортируются. Один provider read error прекращает обход с явным сообщением;
ошибка отдельного аудиофайла не мешает следующим доступным файлам.

Grant дочернего tree URI проверяется по authority и tree ID постоянного
разрешения. Фактический доступ к документу дополнительно проверяет ОС при
открытии descriptor/чтении метаданных; строка URI сама не обходит sandbox.
Прежний readAudio поддерживает как индивидуальный grant, так и tree grant.

Сессией владеет engine, Activity нужна только для picker. CancellationSignal
прерывает поддерживающий отмену запрос провайдера; worker затем закрывает cursor.
При engine detach сигналы отменяются, закрытие курсоров ставится в очередь перед
shutdown. Принятые блокирующие вызовы MediaMetadataRetriever или провайдера
могут закончиться не сразу; мгновенная остановка произвольного системного IO
не гарантируется.

## Импорт и отмена

AndroidImportController последовательно обрабатывает страницы тем же импортом
метаданных/миниатюр/коротких DB-транзакций, что отдельные файлы. Схема БД 9
не меняется. Повтор той же строки URI сохраняет ID, лайки, статистику,
плейлисты, ручные теги и обложки благодаря существующему TrackImportRepository.
Никаких выводов о тождестве по названию/исполнителю не делается.

Папка открывается только один раз за операцию; повторные кнопки блокируются.
UI показывает найденные/обработанные аудиофайлы и неопределённый прогресс:
итоговый размер ещё неизвестен. Кнопка отмены доступна после picker.
Отмена запрещает следующие чтения/записи, освобождает сессию, дожидается уже
принятой операции и сохраняет завершённые транзакции. Закрытие приложения также
дренирует чтение/кэш/DB; поздний picker не запускает новый импорт.
Повторный выбор папки после отмены добавляет оставшиеся файлы.

## Границы пакета

- Папка пока не регистрируется как самостоятельный источник с кнопкой
  пересканирования/удаления. Для обновления нужно выбрать её ещё раз.
- Разные URI одного физического файла, например индивидуальный документ и
  его tree URI или выбор вложенной папки отдельно, пока могут создать разные
  записи. Это прежняя граница URI-идентичности; SHA-256 Android и стабильные
  идентификаторы/алиасы источников нужны перед объединением таких записей.
  Существующие ID/оценки не объединяются по косвенным метаданным.
- Отмена/ошибка/полный обход не удаляют отсутствующие записи и не отзывают
  grants. Учёт источников/неиспользованных grants остаётся отдельной задачей.
- Длительный импорт не получает отдельную dataSync foreground-службу и не
  восстанавливается автоматически после process death. Уже записанная часть
  остаётся; пользователь повторяет выбор папки. Фоновое аудио пакета 19 прежнее.
- Пакет не обещает измеренную скорость массового импорта на телефоне. Чтение
  тегов и DB выполняются последовательно; дальнейшая оптимизация — по измерениям.

## Проверки

6 JVM-тестов обхода: более 64 файлов, вложенность/циклы/дубли, фильтр MIME и
расширений, пустые каталоги/границы порции, close/cancel, ошибка и общий лимит.
Dart-тесты проверяют канал и его ограничения, 130 источников/повтор/правки/лайки,
пустую папку/отмену picker, запрет параллельного запуска, повреждённый файл,
ошибку провайдера, отмену/закрытие на разных await, поздние результаты и drain.
Widget-проверки охватывают кнопки, блокировку и отмену с 200% текстом на телефоне
и в landscape; прежние тесты фона/плеера остаются в полном прогоне.

Физического устройства в сборочной сессии нет. Особенности picker/провайдера,
tree grants после перезапуска и реальные метаданные проверяет пользователь.
[Android: доступ к выбранной папке](https://developer.android.com/training/data-storage/shared/documents-files#grant-access-directory),
[DocumentsContract](https://developer.android.com/reference/android/provider/DocumentsContract).
