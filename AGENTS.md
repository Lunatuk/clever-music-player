# Правила работы с проектом

- Ветки называем `feat/...`, `fix/...`, `refactor/...`, `chore/...` или `docs/...`
  по назначению. Префикс `codex/` не используем.
- Сообщения новых коммитов пишем по-русски и описываем результат изменения.
- Каждая передаваемая пользователю итерация получает новую числовую версию
  `MAJOR.MINOR.PATCH+BUILD` в `pubspec.yaml`. Исправления повышают PATCH,
  функциональные обновления — MINOR, крупные рубежи — MAJOR. При повышении
  старшего компонента младшие обнуляются. BUILD всегда растёт.
- Используем `python tool/release_version.py bump patch|minor|major`.
  Политика выпуска и проверки: [docs/RELEASING.md](docs/RELEASING.md).
- Версию релиза берём из pubspec; при сборке не подменяем её флагами
  `--build-name`/`--build-number`. Android ARM64 собираем без `--split-per-abi`,
  чтобы versionCode совпадал с BUILD. Проверяем метаданные готовых EXE/APK.
- Для каждого выпуска выполняем соответствующие автоматические проверки и
  даём короткий список точечных ручных проверок. Не запускаем несколько
  `flutter test` одновременно в одном checkout на Windows.
